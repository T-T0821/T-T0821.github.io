## 1. RoutineMiku/apkstart {#routinemiku-apkstart}

[GitHub](https://github.com/RoutineMiku/apkstart) ・ 言語: JavaScript ・ ★ 2,637（24h +1,594） ・ ライセンス: MIT

> Windows 上的安卓应用运行器：双击 APK 即装，应用以独立窗口与桌面图标运行，自持 QEMU 运行时

::: v-pre

**一言で:** Windows 上で APK をダブルクリックするだけでインストールし、各 Android アプリをデスクトップアイコン付きの独立ウィンドウとして動かす、Electron 製のランナーです。

**解決する課題:** Windows で Android アプリを動かすには、エミュレータ UI を開いて APK を入れ、アプリを探して起動する、という手順が必要でした。ApkStart は APK の解析・インストール・ショートカット生成までを自動化し、Windows ネイティブアプリに近い操作感で Android アプリを使えるようにします。運用に必要なランタイム(adb、Android Emulator、システムイメージ)も自前で管理します。

**技術的なポイント:**
- Android Emulator(QEMU ベース)と Android 14(API 34)の Google Play x86_64 イメージを使用。自前のハイパーバイザではなく、AOSP/QEMU/adb を土台にしています。
- エミュレータのウィンドウを `SetParent` で埋め込み、タイトルやアイコンを差し替えて、アプリごとの独立ウィンドウに見せます。全画面/ウィンドウモードの切り替えと、アプリごとのサイズ記憶に対応しています。
- シェル部分はサードパーティ依存ゼロで、ZIP/PNG/ICO/AXML/`resources.arsc` の解析を手書きしています。APK からアイコンと名前をオフラインで取り出し、ICO と `.lnk`(デスクトップ+スタートメニュー)を生成します。
- ネットワークは QEMU のユーザーモード NAT で、ホストの NIC を共用します。仮想 NIC やドライバは不要です。ハードウェアアクセラレーションは AEHD または WHPX を使い、利用できない場合はソフトウェアエミュレーションにフォールバックします。
- 起動を速める仕組みとして、quickboot スナップショット(README の実測では冷起動約 23 秒、スナップショット復元約 10 秒)と、起動時のバックグラウンド事前起動(空き時のメモリ常駐は約 1 GB)があります。
- ARM 専用アプリは「ARM 互換モード」で ndk_translation 経由で動かします。README では一部アプリの動作を確認したとしていますが、強いエミュレーション検知を持つアプリは制限される可能性があると明記されています。
- ホストの `ApkStartShared` と Android 側 `/sdcard/ApkStartShared` は、マウントではなく双方向同期です。

**使いどころ:** Windows 上で Android アプリを日常的なデスクトップアプリのように起動したい場合や、WSA 終了後の代替を探している場合に向きます。対象は Windows 10/11 x64 です。ARM 専用アプリや、エミュレーション検知が厳しいアプリでは動作が保証されない点に注意してください。

**始め方:**
```powershell
npm install
npm start          # ランタイム(adb / Emulator / システムイメージ)を初回デプロイ
npm run assoc:on   # (任意).apk のダブルクリック関連付けを登録
```
ビルド不要の場合は、GitHub または Gitee の Releases から `ApkStart-v*-Setup.exe`(約 1.3 GB、ランタイム同梱)か、軽量版のポータブル zip(約 95 MB、初回起動時にランタイムをダウンロード)を入手できます。

:::

## 2. deepseek-ai/chat-demo {#deepseek-ai-chat-demo}

[GitHub](https://github.com/deepseek-ai/chat-demo) ・ [Website](https://deepseek-ai.github.io/chat-demo/) ・ 言語: TypeScript ・ ★ 1,393（24h +703） ・ ライセンス: MIT

> Chat Demo

::: v-pre

**一言で:** DeepSeek API に対して、アプリ側のバックエンドなしでブラウザから直接接続して使える、静的なチャット UI のデモです。

**解決する課題:** DeepSeek API を使ったチャット UI を試したり自前で構築したりする際、通常はサーバー側の実装が必要になります。このリポジトリはブラウザだけで完結する静的サイトとして提供されており、API キーを設定するだけで、会話管理・ストリーミング応答・添付ファイル・音声機能などを備えたチャットを動かせます。

**技術的なポイント:**
- TypeScript 製で、ビルドには rspack を使用します（`rspack.config.ts`）。リンターは oxlint、フォーマッターは oxfmt です。ビルド成果物は `dist/` に静的ファイルとして出力されます。
- アプリケーションのバックエンドは不要で、ブラウザが設定された API サービスへ直接接続します。API キーと設定は localStorage、会話と添付ファイルの原本は IndexedDB に保存されます。
- チャットはデフォルトで `deepseek-flash` モデルを、Anthropic 互換の Messages / Files API 経由で利用します。音声機能は ASR / TTS エンドポイントを使います。検索、リンク読み取り、タイトル生成、`latest_reminder` といった拡張を含むリクエストを送るため、接続先がこれらに対応している必要があります。
- 機能面では、複数会話、プロンプト編集、再生成、メッセージのブランチ切り替え、Deep thinking、検索と出典表示、Markdown / シンタックスハイライト / KaTeX / Mermaid、日英対応、ライト/ダークテーマ、モバイルレイアウトなどを備えています。
- 履歴は ZIP 形式でインポート/エクスポートできます。インポートは既存のローカル会話と添付をすべて置き換えます。エクスポートには API キー、設定、画像以外の添付原本は含まれません。API のデフォルトの接続先は `https://api.deepseek.com` で、`createConfig({ apiOrigin, devServer })` で変更できます。

**使いどころ:** DeepSeek API の動作確認や、バックエンド不要の自前チャット UI のベースとして、静的ホスティングやローカルで手軽に動かしたい場合に向いています。`dist/index.html` を直接開く場合は、ブラウザが `file://` でのストレージに対応していることと、API サービスがそのクロスオリジンリクエストを許可していることが必要です。

**始め方:**
Node.js 22.12 以上と pnpm が必要です。

```sh
git clone https://github.com/deepseek-ai/chat-demo.git
cd chat-demo
pnpm install
pnpm dev
```

http://localhost:8090 を開き、初回のチャット前に設定画面で API キーを入力します。静的サイトとして出力する場合は `pnpm build` を実行します。

## 3. GoogleChrome/modern-web-guidance {#googlechrome-modern-web-guidance}

[GitHub](https://github.com/GoogleChrome/modern-web-guidance) ・ [Website](https://goo.gle/modern-web-guidance) ・ ★ 12,398（24h +1,394） ・ ライセンス: Apache-2.0

> Keep your coding agent up to date with the latest web best practices

::: v-pre

**一言で:** コーディングエージェントに、モダンな Web プラットフォームのベストプラクティスとブラウザ互換性情報を「スキル」として組み込み、レガシーなコードパターンを避けさせるための CLI／スキル集です。

**解決する課題:** LLM の学習データには古いコードが大量に含まれるため、エージェントは今ではネイティブ機能で済む処理にも、肥大化した JavaScript やレガシーな実装を生成しがちです。API の存在自体は知っていても、実運用レベルのモダンな実装パターンの情報量が不足していることもあります。本プロジェクトは、専門家が整理したガイドをエージェントのコンテキストに直接渡すことで、このギャップを埋めることを狙っています。

**技術的なポイント:**
- スキルの CLI（`npx modern-web-guidance`）が、`search`（ガイド検索）、`retrieve`（ID 指定でガイド取得）、`legacy-scan`（コードベース内のレガシーパターン検出）といったコマンドを提供し、該当ガイドをエージェントのコンテキストに返します。
- カバー範囲は、README の機能一覧によると 250 の Web 機能（CSS・レイアウトで 140 機能など）です。View Transitions、コンテナクエリ、Anchor Positioning、Popover API、`scheduler.yield`、組み込み AI（翻訳・要約・言語検出）などが含まれます。
- ガイドはトークン効率を重視しており、評価（eval）を実行して、モデルが既に知っている最低限の内容は削る方針とのことです。評価結果は Eval Dashboard で公開されています。
- 重いポリフィルやレガシーライブラリではなく、軽量で妥当なフォールバックを推奨する方針です。パフォーマンスやアクセシビリティ面で、ブラウザが最適化できるプラットフォーム標準 API を優先します。
- Google Chrome、Microsoft Edge、Mozilla Firefox、MDN の各チームとコミュニティが運営に関わっているとされています。ライセンスは Apache-2.0 です。なお、このリポジトリは配布用で、ソースコードは別リポジトリ（modern-web-guidance-src）にあります。

**使いどころ:** Claude Code など AI コーディングエージェントでフロントエンドを実装する際に、モダンな CSS／Web API ベースのコードを生成させたい場合に向いています。また、`legacy-scan` を使って既存コードベースの近代化候補を洗い出す用途も想定されています。

**始め方:**
```shell
# 対話式ウィザードでインストール
npx modern-web-guidance@latest install

# インストールせずに試す
npx modern-web-guidance@latest search "animate a dialog modal backdrop"
npx modern-web-guidance@latest retrieve "animate-to-from-top-layer"
npx modern-web-guidance@latest legacy-scan .
```

- エディタ UI なしで Node.js からコンテンツモデル、コマンド、計算を使う Headless 利用も可能です。

**使いどころ:** 自社の Web アプリに表計算や文書エディタを埋め込み、アプリのデータと連携させたい場合や、エージェントが同じ API でシートを編集・計算する仕組みを作りたい場合に向きます。共同編集や XLSX 変換が必要なときは、別ライセンスの Server SDK などが必要になる点に注意してください。

## 15. dulaiduwang003/Pavise-Game {#dulaiduwang003-pavise-game}

[GitHub](https://github.com/dulaiduwang003/Pavise-Game) ・ [Website](https://pavise.club) ・ 言語: C# ・ ★ 1,750（24h +219） ・ ライセンス: GPL-3.0

> Open-source Windows game resource manager. Suppresses background processes, gives games exclusive CPU cores, steers device interrupts off game cores, applies per-game GPU driver, memory and power policies, and restores every change after play. No injection, no telemetry. GPL-3.0.

::: v-pre

**一言で:** Windows ゲーム向けに、プレイ中だけバックグラウンド処理を抑制し、CPU コアや電源・GPU などの設定をゲームごとに最適化して、終了後に元へ戻す C#（WinForms）製のリソース管理ツールです。

**解決する課題:** ブラウザ、ランチャー、アップデータ、Windows 標準のバックグラウンド処理は、ゲームと CPU・ディスク I/O・GPU を取り合います。Pavise はこの競合を減らし、手持ちのハードウェア性能をゲームに多く振り向けることを狙っています。変更はセッション単位で記録され、プレイ後に復元されます。

**技術的なポイント:**
- **バックグラウンド抑制が中核:** 対象プロセスの CPU・ディスク I/O・メモリページ・GPU の優先度を下げ、効率モード（EcoQoS）を要求します。Job による CPU クォータやコア制限も使います。DiagTrack、WSearch、Widgets などの Microsoft 組み込み対象には、Normal で CPU 5%・物理コア最大 2、Aggressive で 2%・最大 1 コアの制限がかかります。
- **2 つのモードと 3 段階の強度:** Smart は負荷とフォアグラウンド状態に応じて対象範囲を調整します。Competitive はゲーム切り替え中も抑制を維持します。強度は Off / Normal / Aggressive で、モードとは別に設定します。
- **ゲームごとの細かな設定:** CPU 配置（P/E コア、CCD、キャッシュドメイン、手動選択）、レンダースレッドのアフィニティ、電源プラン、タイマー解像度、メモリのスタンバイリスト整理、NVIDIA 設定や HAGS などを個別に構成できます。システム診断機能には GPU 割り込み配置の確認と検証・ロールバックも含まれます。
- **安全性への配慮:** 説明文では、インジェクションとテレメトリを使わないとされています。ホワイトリストで、ゲーム本体、依存プロセス、アンチチートやストリーミングツールなどを保護します。異常終了後の復旧ガードも備えます。
- **検証可能性:** GPL-3.0 でソースが公開されています。ビルドは Windows 標準の .NET Framework C# コンパイラと PowerShell で行え、Visual Studio は不要です。公開リグレッションテストと実験資料も用意されています。

**使いどころ:** 常駐アプリが多い PC で、フレームタイムの安定性や操作の応答性を、設定を戻せる形で試したいときに向きます。ただし、効果はゲーム・ハードウェア・ドライバー・負荷によって変わるため、再現できるシーンでの比較が推奨されています。

注意点として、動作には管理者権限が必要です。プロセススケジューリング、サービス、電源設定、レジストリ、PowerShell を扱うため、セキュリティソフトに検知される可能性があります。他のプロセス優先度・アフィニティ管理ツールとの併用は避けるよう書かれています。


出力は `build\Pavise.exe` です。ビルド済みの配布物は GitHub Releases から入手できます。

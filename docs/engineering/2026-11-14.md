# 2026-11-14 の開発手法・エンジニアリング動向

> InfoQ・Martin Fowler・Publickey・arXiv から自動収集し、Claude（`claude-sonnet-5-5`）が要約しています。詳細は各リンク先の一次情報を確認してください。

## 今日の動向

AI コーディングエージェントの運用が前提になりつつあり、責任の所在、レビュー、技術的負債、PR の品質といった開発プロセス面の課題と、障害診断・可観測性へのエージェント活用が目立ちます。インフラ側では、Google Cloud の日付ベース API バージョニングや AWS 公式エミュレータなど、開発・運用基盤の整備が進んでいます。研究ではエージェント生成コードの検証・テスト手法や、エージェントの変更の可視化に関する報告が出ています。

### Google、本番 AI エージェントの失敗を診断する AQuA をオープンソース化

[Google Open Sources Ambient Quality Agent (AQuA) to Diagnose Production AI Agent Failures](https://www.infoq.com/news/2026/11/google-ambient-agent-prod/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=global) ・ InfoQ ・ 2026-11-13

Google は、本番の AI エージェントのセッションを分析し、繰り返し起きる失敗パターンを検証して、デプロイ済みソースのスナップショットに対して根本原因を調査するリファレンス実装 AQuA を公開しました。32 セッションのリプレイでは、プロンプト変更後に座席選択のバイパスが 15 セッションから 2 に、食事の好みの欠落が 7 から 0 に減ったとされています。

**影響・使いどころ:** 本番エージェントの品質改善を、ログ分析と原因調査のループとして実装する際の参考になります。

[Netflix Turns Operational Data Into a Knowledge Graph for AI-Driven Observability](https://www.infoq.com/news/2026/11/netflix-ai-driven-observability/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=global) ・ InfoQ ・ 2026-11-13

**影響・使いどころ:** 運用データの意味付けを整えることが、AI を使った障害調査の前提になり得ることを示す事例です。

### Google Antigravity にクラウド上で動く「リモートエージェント」機能

[Google Antigravity、クラウド上でAIエージェントが働く「リモートエージェント」機能を搭載。就業時間外でもAIエージェントは働き続ける](https://www.publickey1.jp/blog/26/google_antigravityaiai.html) ・ Publickey ・ 2026-11-12

Google の AI エージェント開発環境 Antigravity に、クラウド上でエージェントが動作する「リモートエージェント」が追加されました。就業時間外でもエージェントが作業を続けられる位置付けです。

**影響・使いどころ:** 非同期にエージェントへ作業を任せる開発フローを検討する際の選択肢が増えます。

### AWS 公式の「AWS エミュレータ」が正式リリース

[AWSをローカルマシン上でエミュレートする、AWS公式の「AWSエミュレータ」正式リリース](https://www.publickey1.jp/blog/26/awsawsaws_1.html) ・ Publickey ・ 2026-11-12

AWS が、ローカルマシン上で AWS の API をエミュレートする「AWS エミュレータ」を正式リリースしました。ダウンロードしてインストールすれば無料で使え、AWS アカウントは不要です。

**影響・使いどころ:** クラウドに接続せずに開発やテストを回せるため、ローカル開発や CI の構成を見直す契機になります。

### Google Cloud、Compute Engine API を不変の日付ベースバージョンへ

[Google Cloud Moves the Compute Engine API to Immutable Date-Based Versions](https://www.infoq.com/news/2026/11/compute-engine-api-versioning/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=global) ・ InfoQ ・ 2026-11-14

Compute Engine API で日付ベースのバージョニングが一般提供となり、可変だった /v1 に加えて 2026-09-01 のような四半期ごとの不変スナップショットを、ヘッダーまたはクエリパラメータで指定できます。新バージョンではデフォルト値、エラー形式、IAM チェックが変わる場合がありますが、/v1 の利用者には影響しません。

**影響・使いどころ:** API 利用側は、バージョンを固定して変更を計画的に取り込む運用を設計しやすくなります。

### Martin Fowler：Generated Glossary（生成された用語集）

[Bliki: Generated Glossary](https://martinfowler.com/bliki/GeneratedGlossary.html) ・ Martin Fowler ・ 2026-11-12

## 論文

### Rasoi：コーディングエージェントによる構造変更を評価するビジュアル差分

[Rasoi: Visual Diffs for Evaluating Structural Changes Made by Coding Agents](https://arxiv.org/abs/2611.16293) ・ arXiv ・ Riya Sahni, Aryan Kaul, Anushka Bhatnagar, Xuanming Zhang ほか

エージェントによる大規模な変更では、ロジックの重複、依頼範囲外のモジュール変更、機能の削除、アーキテクチャのずれが、表面上は正しく見えても起こり得ます。ビジュアル差分が、開発者による構造変更の理解と評価をどう助けるかを調べています。

**注目ポイント:** 行単位の diff では見えにくい、エージェント由来の構造的な変化をレビューする方法を扱っています。

### AI 支援開発における技術的負債のリスク：実務者の知見

[Technical Debt Risks in AI-Assisted Software Development: Insights from Practitioners](https://arxiv.org/abs/2611.15310) ・ arXiv ・ Nazia Jahan, Nafisa Alam, Sourov Debnath, Arafat Rahman ほか

137 人へのアンケートと 20 人へのインタビューによる混合手法で、AI 生成コードに関連する技術的負債について、認識されるリスク、保守への影響、検証の実践などを 10 の技術的負債の観点から調べています。調査対象はバングラデシュのソフトウェア専門職です。

**注目ポイント:** AI コーディング支援の普及に伴う保守性の懸念を、実務者の声から確認できます。

### OSS プロジェクトでメンテナーが指摘した AI slop PR の実証研究

[An Empirical Study of Maintainer-Identified AI Slop Pull Requests in Free and Open Source Software Projects](https://arxiv.org/abs/2611.15159) ・ arXiv ・ Hugo Raskin, Xavier Devroey, Benoît Vanderose

GenAI により貢献の障壁が下がり、低品質で低価値な生成 PR である「AI slop PR」が現れています。本研究は、メンテナーが AI slop と特定した PR の発生状況を、プロジェクト単位で調べています。

**注目ポイント:** OSS メンテナーの負荷やレビュー運用に直結する課題を、プロジェクトレベルで扱っています。

### Spec-Driven PBT：コード仕様から意味的不変条件を導出するエージェント型プロパティベーステスト

[Spec-Driven PBT: Deriving Semantic Invariants from Code Specifications for Agentic Property-based Testing](https://arxiv.org/abs/2611.15920) ・ arXiv ・ Aditya Shukla, Kartik Gupta, Ali Alavi, Pashootan Vaezipoor ほか

AI エージェントが自然言語の仕様から実装を生成し、コードがレビュー速度を超えて作られる状況を前提にしています。仕様から意味的な不変条件を導出し、LLM エージェントによるプロパティベーステストに活用する手法を提案しています。

**注目ポイント:** 生成コードの検証を、仕様に基づくテストで補う方向性を示しています。

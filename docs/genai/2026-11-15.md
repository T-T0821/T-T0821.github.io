### 1. Actor・Judge・Teacher：長期エージェントにおける決定モデルの理解 {#paper-1}

Hugging Face Daily Papers ・ Haochen Liu, Qianhao Zhu, Zixuan Wang, Dingming Li ほか ・ [論文を読む ↗](https://arxiv.org/abs/2611.17167)

<small>原題: Actor, Judge, or Teacher? Understanding Decision Models in Long-Horizon Agents</small>

決定モデルを、行動選択（Actor）、行動評価（Judge）、強化学習用の教師（Teacher）として使う場合を、ALFWorldとWebShopで比較した。行動主体としては劣っていても、教師としては有効な可能性を検討している。

::: tip 🔍 注目ポイント
判断特化モデルをエージェントの評価・学習に使う観点を示している。
:::

::: info 📝 落合フォーマット

**どんなもの？**

意思決定モデル（選択肢と確率などの型付き出力を返す事前学習モデル）を、Actor（行動選択）、Judge（記録済み軌跡の行動評価）、Teacher（RL学習時の各行動スコアリング）の3役割で同一タスク上で比較分析した研究。行動が下手な意思決定モデルでも、適切な問いと文脈を与えれば優れた教師になり得ることを示した。

**先行研究と比べてどこがすごい？**

先行研究は意思決定モデルを主に Actor としての行動性能で評価していたが、本研究は同じモデルを3役割で体系的に比較し、Actor性能がJudge・Teacherとしての価値を反映しないことを示した。また、問い（Value か Progress か）と文脈（Prefix か Hindsight か）のどちらが評価の質と学習効果を決めるかを要因ごとに切り分けた点が新しい。

**技術や手法のキモはどこ？**

3つの専用意思決定モデル（JEV、Decider v1.2、GPT Decisions）と3つの汎用LLMを ALFWorld・WebShop で比較。Judge では文脈を Prefix（行動までの軌跡）か Hindsight（全軌跡）、問いを Value（タスクが成功するか）か Progress（その行動が目標達成に役立ったか）に変えて各行動を [0,1] でスコア化する。Teacher では凍結した JEV のスコアをロールアウト群内で中心化し、重み λ=0.5 で GRPO の結果アドバンテージに加算する（標準偏差での正規化はしない）。

**どうやって有効だと検証した？**

Actor としては全6モデルが依存サブゴールのタスクで低成功率となり、JEV は独立2サブゴールの Pick2 で70.8%、順序依存タスクでは14.7%、全体で42.9%だった。Judge では Progress が Value より milestone と no-op の差を拡大し（0.36 対 0.05）、Hindsight でスコアが上がった。Teacher では Hindsight+Progress が Qwen2.5-1.5B の成功率を GRPO 比で ALFWorld 72.8%→82.9%、WebShop 56.8%→71.4% に改善し、7B でも ALFWorld 77.6%→83.8%、WebShop 66.1%→73.6% に向上した。API コストは1回の学習あたり約22〜30 USD。

**議論はある？**

実験は最大30行動のテキスト環境2種に限られ、ソフトウェア開発やツール利用などより長く多様な依存関係を持つタスクで有効かは未検証である。Hindsight 判定は全軌跡が必要なためオンラインでの行動フィルタリングには向かず、JEV や GPT Decisions は閉じたモデルで何が良い Judge を生むかも特定できない。今後は Decider v1.2 のような open-weight モデルを行動貢献の判定向けに直接学習することが挙げられている。

**次に読むべき論文は？**

- Group-in-Group Policy Optimization for LLM Agent Training (GiGPO)：本論文の GRPO ベースラインの出典であり、同一状態からの行動比較によるステップレベルのクレジット割り当てを理解できる。
- Hindsight Credit Assignment：行動の後に起きた結果を使って貢献度を判定する考え方の原典で、本論文の Hindsight 文脈の理論的背景になる。
- Milestone-guided policy learning for long-horizon language agents：本論文が milestone 行動の定義に引用しており、サブゴール達成に基づく長期エージェントの学習手法を比較できる。

:::

### 2. 記憶を鵜呑みにしない：根拠リンク付きメモリでLLMエージェントの劣化を低減 {#paper-2}

Hugging Face Daily Papers ・ Yukyeong Lee, Yumin Choi, Jinheon Baek, Sung Ju Hwang ほか ・ [論文を読む ↗](https://arxiv.org/abs/2611.14320)

<small>原題: Don't Just Trust Your Memory: Evidence-Linked Memory Reduces Memory-Induced Degradation in LLM Agents</small>

過去の軌跡から得た教訓が誤っている場合に、エージェントが記憶なしより悪化する問題を扱う。教訓を元の軌跡と結びつけて検証できるWikiTraceを提案した。

::: tip 🔍 注目ポイント
エージェントの外部メモリ設計で起こりうる失敗への対策として実務的である。
:::

::: info 📝 落合フォーマット

**どんなもの？**

LLM エージェントの外部メモリが、メモリなしなら解ける課題を失敗させる「memory-induced degradation」を引き起こす問題に取り組んだ研究。教訓（insight）をその元となった軌跡へのリンク付きで保存する証拠リンク型メモリ WikiTrace を提案し、エージェントが教訓を元の軌跡で確認してから使えるようにした。

**先行研究と比べてどこがすごい？**

既存手法は教訓だけを渡し、その根拠となる軌跡を提示しないため、成功/失敗ラベルのみから推定された誤った教訓をエージェントが検証できなかった。本研究は Gain（失敗→成功）と Regression（成功→失敗）を分けて測り劣化を明示的に評価した点、および教訓から要約（compilation）・生軌跡へ辿れる3層構造と、テスト時に必要に応じて降りて確認・修正する仕組みを組み合わせた点が新しい。

**技術や手法のキモはどこ？**

メモリを insight（簡潔な教訓）→ compilation（その実行が成功/失敗した理由の要約）→ raw trajectory（生の軌跡）の3層でリンクし、各層に索引を付ける。1実行あたり最大3件の insight を独立に抽出し、更新・削除はしない。テスト時はエージェントに全 insight と類似する過去3実行を最初に渡し、insight が行動に必要な詳細を欠く、他と矛盾する、失敗実行由来である、または行動が失敗した場合に、読み取り専用ファイルとして mount されたメモリを read/bash で検索して元の実行へ降り、詳細補完や教訓修正を行ってから行動させる。

**どうやって有効だと検証した？**

ALFWorld、ScienceWorld、PlanCraft、AppWorld、τ3-bench Retail の5ベンチマーク・8スイートで、deepseek-v4-flash を用い3試行平均で評価した。WikiTrace は全スイートで最高となり、平均 90.2 で No Memory の 79.5 を上回り、同じ insight のみを与える Insights Only（87.0）も 3.2 ポイント上回った。Regression は 4.5%（Insights Only 6.5%、メモリなし再実行 9.7%）に低下し、GLM-5.3-flash でも同様の傾向が確認された。テスト時コストは Insights Only の 1.17 倍で、既存手法の構築予算を増やしても優位は維持された。

**議論はある？**

メモリは二値の成功/失敗ラベルから作られるため、compilation の失敗原因診断や insight 自体が誤りうる。リンクは検証を可能にするだけで正しさを保証しない。また全 insight を最初のメッセージに入れるためプロンプトがメモリ量に比例して増え、メモリが大きい場合に必要な insight をどう探すかという検索問題は未解決である。劣化原因や降下ラベルは LLM 判定に基づくため、エージェントの推論記述を反映するにとどまる。

**次に読むべき論文は？**

- ReasoningBank: Scaling agent self-evolving with reasoning memory：成功・失敗両方の軌跡から推論戦略を蒸留する代表的な比較対象で、WikiTrace が失敗経験の扱いで何を改善したかを理解できる。
- ExpeL: LLM agents are experiential learners：自由形式ルールを蒸留・更新する手法で、本論文が誤った教訓の例として挙げたベースラインの仕組みを確認できる。
- Useful memories become faulty when continuously updated by LLMs：メモリ更新で教訓が劣化する問題を扱っており、memory-induced degradation の背景理解に役立つ。

:::

### 3. Infrathon：長期的なAIインフラ最適化を行う言語エージェントのベンチマーク {#paper-3}

Hugging Face Daily Papers ・ Zhengyu Hu, Zheyuan Xiao, Yike Wang, Hamish Ivison ほか ・ [論文を読む ↗](https://arxiv.org/abs/2611.11995)

<small>原題: Infrathon: Benchmarking Language Agents for Real-World, Long-Horizon AI Infra Optimization</small>

6モデル・150回・24時間予算の実行で、AIインフラ最適化を長期で評価した。評価期間によりモデルの順位が変わり、人手の基準を上回る解を見つけるエージェントもあった。

::: tip 🔍 注目ポイント
エージェントの長時間タスク評価で、短時間評価では見落とされる点を示している。
:::

::: info 📝 落合フォーマット

**どんなもの？**

AIインフラ（演算子・モジュール・システムの3レベル）の最適化を、12〜24時間という長時間の予算でフロンティアLLMエージェントが継続的に改善できるかを評価するベンチマーク「Infrathon」を提案した研究。実在のOSS・研究プロジェクトに基づく25タスクと、タスク作成ツールInfrathon-buildを提供する。6モデル×25タスク=150ランを総計1万GPU時間超で評価している。

**先行研究と比べてどこがすごい？**

既存のベンチマークは、タスク範囲、実行時間（Φ-Benchは大半が1.5時間以内）、公開GPUタスクのいずれかが限定的だった。Infrathonは、AIインフラ専用で3レベルを網羅し、12〜24時間の長時間予算とTFLOP/sなど上限のない指標を備えた最初のベンチマークだと主張している。また、Controllerによる指示違反・報酬ハッキングの検査と、非公開テストを行うJudge環境の分離も特徴である。

**技術や手法のキモはどこ？**

各タスクをτ=(ワークスペース, 公開テスト, 非公開テスト, リソース, 時間予算)として定義する。実行はWork環境（エージェントが開発・公開テスト・提出）、Controller（提出回数の制限と、GPT-6.1 Solによる指示遵守・報酬ハッキングの検査）、Judge環境（非公開テストの実行とスコア返却）の3要素で構成する。Work環境とJudge環境は別コンテナにして非公開テストを秘匿し、早期終了しようとするエージェントにはstop hookで作業継続を促す。ランごとに時間予算内の最良の有効スコアを報告する。

**どうやって有効だと検証した？**

6モデル×25タスクの150ランで評価した結果、Claude Opus 5.5が17タスクで最良（平均ランクスコア91.2）、GPT-6 Astraが6タスクで最良（75.2）だった。順位は予算に依存し、25%時点ではAstraが首位、50%時点ではClaudeが首位となった。150ランのうち135ランで後半に最良スコアが改善し、Quant-VideoGen KV Codecでは、ClaudeがKVキャッシュ圧縮率を人手設計コーデックの6.82倍から19.86倍に引き上げ、映像品質も向上した。

**議論はある？**

軌跡分析から、公開テストは通るが指示に違反する解、実際には変更が反映されていないコードの性能測定、早すぎる完了宣言が、継続的改善の妨げになると示された。同一GPU時間での比較では、モジュール・システムタスクは長時間実行が有利だが、演算子タスクは短時間の複数試行（best-of-n）でも競争力があり、課題の種類により最適な探索戦略が異なる。なお、本文の抜粋からは、評価対象が6モデルで1タスクあたりの試行回数が限られる点や、ランごとの分散については確認できない。

### 4. InfraRSI：学習インフラの再帰的自己改善 {#paper-4}

Hugging Face Daily Papers ・ InfraRSI Team, Yuchuan Tian, Haocheng Mei, Ye Yuan ほか ・ [論文を読む ↗](https://arxiv.org/abs/2611.11558)

<small>原題: InfraRSI: Harnessing Recursive Self-Improvement for Training Infrastructure</small>

分散LLM学習の起動設定やカーネル、通信スケジュールを、5段階のワークフローで検証しながら最適化するエージェントのハーネスを提案した。報酬ハッキング防止のため、編集範囲とタスク契約を固定する。

::: tip 🔍 注目ポイント
学習基盤の最適化をエージェントに任せる際の安全な設計例である。
:::

::: info 📝 落合フォーマット

**どんなもの？**

分散LLM学習の起動設定（launch knobs）とソースコードパッチを同時に最適化し、人間の自由記述の指示を検証済みの学習基盤高速化へ変換するエージェント型ハーネス InfraRSI を提案した。init→doctor→run→report→apply の5段階ワークフローで、run中にオンラインで事前分布を修正し、クラスタ間で経験を蓄積する2段階のRSIループを構成する。

**先行研究と比べてどこがすごい？**

従来のRSIは単一アルゴリズムや単一カーネルが対象だったが、本研究は起動設定・演算子実装・通信スケジュールが密結合する学習基盤全体を対象とする。また、単一の現行解から貪欲に進む既存のコーディングエージェントやノブのみのチューナーと異なり、多様な経験初期化、OOM失敗も含めた全試行からの時間・メモリモデル、固定タスク契約による報酬ハッキング防止を組み合わせている。

**技術や手法のキモはどこ？**

initで編集可能範囲と、ワークロード・損失・タイミング不変条件の固定タスク契約をロックし、doctorでベースラインのフェーズ分解とクラスタのノイズ較正を行う。runでは、経験由来の3つの多様な初期構成から始め、全試行に対するCholeskyベイズ線形の時間サロゲートと、OOMを右打ち切りとして扱うTobitメモリモデルを更新する。これらでLLMの速度予測を経験的に修正し、OOMした高効果設定をメモリ節約設定と組み合わせるバンドル補完、高影響ノブの探索、検証済みパッチの積み重ねを行う。最後に上位候補をベースラインとの背中合わせ再実行で検証し、16個の不変条件で報酬ハッキングや数値ずれを排除して、ハードウェア正規化した結果を経験バンクに書き戻す。

**どうやって有効だと検証した？**

Qwen3.5-9B（8×H100）、Gemma-4-26B-A4B MoE（8×H200）、Qwen3.8-27B（8×H200）、2ノードQwen3.5-35B-A3B MoE（16×H100）の4ワークロードで評価し、幾何平均1.83倍の高速化、平均MFU 17.4%→30.0%（Gemma MoEで最大2.75倍）を達成した。RE-Bench（1.37倍）、Auto-Research（1.34倍）、ノブのみのOptiCo（1.23倍）を全タスクで上回った。さらにQwen3.5-9Bでは、GPU種別をまたぐ経験転移により最終速度向上が1.70倍から1.82倍に改善した。1,212回の実行に対するオフライン再検証では400件（33.0%）が不正として棄却された。

**議論はある？**

本文には、新しいホストへ移す際はそのホストで新たにベースラインを取り直す必要があるという制約が書かれている。評価は4ワークロードのHopper世代GPU（H100/H200）が中心で、経験転移の効果は主にQwen3.5-9Bの制御実験で示されているため、他のアーキテクチャや大規模構成への一般化は今後の検証課題である。また、ソース経路の監査には人手のレビューが含まれる点も留意が必要である。

- Liger Kernel: Efficient Triton kernels for LLM training：本論文の発見でメモリ節約パートナーとして登場する融合カーネルで、メモリと速度のトレードオフを理解する助けになる。

### 5. オンポリシー蒸留はどこまで学習・推論のミスマッチに耐えられるか {#paper-5}

Hugging Face Daily Papers ・ Cong Yu, Ziting Wang, Songlin Jiang, Sitong Zhang ほか ・ [論文を読む ↗](https://arxiv.org/abs/2611.11450)

<small>原題: How Much Training-Inference Mismatch Can On-Policy Distillation Tolerate?</small>

量子化推論や非同期ロールアウトによる学習と推論のずれが、オンポリシー蒸留に与える影響を調べた。かなりのミスマッチを許容できるという結果が報告されている。

::: tip 🔍 注目ポイント
推論コスト削減のための量子化・非同期化の判断材料になる。
:::

::: info 📝 落合フォーマット

**どんなもの？**

On-policy distillation（OPD）で、量子化推論や非同期ロールアウトが生む学習・推論間ミスマッチをどこまで許容できるかを実測した研究。許容量を「ミスマッチ予算」として定義し、事前に安全な構成を選別する軽量な採否チェックを提案している。予算内でFP8や非同期を使うことで、メモリと学習時間の両面で効率化できることも示した。

**先行研究と比べてどこがすごい？**

量子化（ビット幅）、非同期（古さ）、重みノイズという異なる要因を、トークンあたりKL（nats/token）という共通尺度で比較できるようにした点が新しい。また、OPDはRLより遥かにミスマッチに強いこと、RL由来のトークン単位補正がOPDでは効果がなく、プレフィックスのずれという補正できない誤差が残ることを示した。

**技術や手法のキモはどこ？**

エンジンの次トークン分布qと学習側の分布pθのトークン平均KL（式2）をミスマッチ量D(c)と定義し、標準BF16エンジンとの保持テストKL（教師との一致度）の相対悪化Δ(c)が閾値τ=0.20以上で有意なら失敗と判定、通過/失敗するDの間を経験的な予算区間として求める。採否チェックは、候補エンジンで少量（16問×2応答）を生成し、標準BF16エンジンで再採点したKLを安全係数α=1.5付きで許容線L=0.41と比較する（学習不要・1GPU）。さらに誤差を、トークン単位誤差Tとプレフィックスのずれ Sに分解して分析している。

**どうやって有効だと検証した？**

DeepSeek-R1-Distill-Qwen 7B/1.5BとLlama-3.2-3Bの3組で200ステップ蒸留し、7Bでは17構成を比較した。7Bでは標準エンジンの200倍超となるD≤0.184でも通過（Δは-5.0%〜+6.4%）、D≈0.39で+23%悪化して失敗し、予算区間は[0.184, 0.39]。事前に決めた8件の判定はすべて的中し、6構成の確認は24分、FP8でKVキャッシュ容量は1.93倍以上、FP8＋非同期（k=8）で同品質に1.62倍速く到達した。RLはREINFORCEが3構成、GRPOが2構成で崩壊し、スコア中心化やTISはOPDを改善しなかった。

**議論はある？**

予算は生徒モデルや品質基準に依存し、1.5Bでは同程度のミスマッチでも大きく劣化するため、モデルごとに較正が必要である。採否チェックは境界付近で未検証で、学習中のミスマッチは推定値の1.56〜1.68倍となり安全係数1.5を超えた。また1構成1回の実験が中心で、小さい生徒モデルでは予算区間を完全には確定していない。

**次に読むべき論文は？**

- On-Policy Distillation of Language Models: Learning from Self-Generated Mistakes：OPD（GKD）の基礎となる手法で、本研究の前提となる更新式を理解できる。
- Your Efficient RL Framework Secretly Brings You Off-Policy RL Training：RLでの学習・推論ミスマッチと切り捨て重要度サンプリング補正の出発点であり、本研究のRL側の比較対象を理解できる。
- Defeating Nondeterminism in LLM Inference：標準エンジンでも生じるミスマッチの原因と、厳密一致による除去の考え方を学べる。

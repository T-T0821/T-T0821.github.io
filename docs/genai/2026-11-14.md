## 📄 論文

### 1. SO-Arena：System Oneモデルの能力範囲と判断の信頼性を測るベンチマーク {#paper-1}

Hugging Face Daily Papers ・ Lichen Li, Ziping Dong, Sicheng Feng, Qi Li ほか ・ [論文を読む ↗](https://arxiv.org/abs/2611.15777)

<small>原題: SO-Arena: Benchmarking the Capability Spectrum and Reliability of System One Models</small>

長いトークン生成なしに素早く判断するSystem Oneモデルを対象に、11分野・5つの能力ファミリーで能力の幅と判断の信頼性を評価するベンチマークを提案している。参照ラベルは信頼できる情報源に基づき、モデルが見る入力と照合して人手で検証されている。

::: tip 🔍 注目ポイント
高速な判断型モデルを、集計スコアだけでなく細かな能力と信頼性の観点で比較できる点が注目される。
:::

::: info 📝 落合フォーマット

**どんなもの？**

System One モデル（Jev のように 1 回のフォワードパスで事前定義された選択肢上の確率分布を返す決定モデル）の「能力スペクトル」と「判断の信頼性」を測るベンチマーク SO-Arena を提案した研究。11 ドメイン・5 つの能力ファミリーにわたる 2,919 タスク（静的 2,300、環境ベース 619）で構成され、21 モデルを評価している。

**先行研究と比べてどこがすごい？**

参照ラベルを信頼できる出典から取り、モデルに見える入力と照らして人手で検証する点、ドメインごとの難易度ティアで性能差を細かく識別する点が特徴である。さらにサンドボックスでの対話的評価（行動選択と完了検証）に加え、精度とは別に「選択肢の並べ替えに対する安定性」と「正解選択肢が欠けた場合の認識」を合成した信頼性スコアを導入し、能力と信頼性を相補的な軸として扱っている。

**技術や手法のキモはどこ？**

各インスタンスを x=(s,q,C) と定式化し、choice・noul（yes/no）・score（順序評価）の 3 形式で統一的に出力させる。能力スコア C は各ドメインの最難ティア（Math は hard と very hard）の平均を、全ドメイン等重みで平均して求める。信頼性は、12 通りの並べ替えで答えが保たれる割合を偶然水準で補正した順序安定性 S と、正解選択肢を除いた場合の p_null による AUC から求める欠落識別 N=2AUC−1 とを算出し、両者が正のときのみ幾何平均 R=√(SN) とする。

**どうやって有効だと検証した？**

21 モデル（System One 16 のオープンウェイト、自動切替 1、クローズド決定 API 2、System Two 参照 2）を評価した。System Two の GPT-6 Sol と Luna が全 System One モデルを上回り、最強の GLiDE と KnowLine-31B は Luna に約 10 ポイント差で及ばないが、オープンウェイトの System One は 1 タスク 0.3 秒以内で、GPT-6 Sol/Luna より数十倍高速だった。信頼性は能力順位と一致せず、最も信頼性が高い JevAny-27B と Jev API 1.14 は性能順位で 18 モデル中 8 位と 6 位であり、順序安定性は性能にほぼ追随する一方、欠落識別は性能との相関が弱かった。ドメイン別には、直接的な意味判断では System Two と同等、細粒度の根拠付き判断ではより大きいバックボーンが効き、多段導出（Math など）では思考の追加が効く（StartLux Auto の Math は 50.8 から 92.5）という結果だった。

**議論はある？**

ティアは各ドメイン内で定義されており、ドメイン間では較正されていない。また、自由記述の応答を要するタスクは対象外で、バックボーン比較は同一ファミリー内の 2 サイズに限られ、サイズ以外の差（Qwen3.5 と Qwen3.8 の世代差など）が混在している。今後は能力と信頼性の両面での System One モデルの改善が課題として挙げられている。

**次に読むべき論文は？**

- General decision models: Benchmarking and insights beyond Jev：JEval として 10 の応用ドメインを扱う、本研究と最も近い決定モデル評価であり、位置づけを比較できる。
- Releasing the inner Jev: A simple recipe for open decision models：OpenDecisions の難易度ティアや摂動を含み、オープンな決定モデルの作り方と評価を理解するのに役立つ。
- System1-Arena: Which decisions can be left to system 1?：System One に任せられる判断を探る関連ベンチマークであり、本研究の問題設定と比較できる。

:::

### 2. DeepStress：ディープサーチエージェントのストレステスト {#paper-2}

Hugging Face Daily Papers ・ Ismael Rousseau, Geraldine Damnati, Frederic Bechet ・ [論文を読む ↗](https://arxiv.org/abs/2607.13920)

<small>原題: DeepStress: Stress-Testing Deep Search Agents</small>

検索エージェントに、信頼性・関連性・事実性を独立に制御した劣化証拠を与えて動作を調べる動的な評価枠組みを提案している。最終回答を5分類で分析し、慎重な振る舞いを評価する新指標RASとCoPRASも導入している。

::: tip 🔍 注目ポイント
低品質な情報源に対するエージェントの頑健性を再現可能な形で測れる点が実務でも役立つ。
:::

::: info 📝 落合フォーマット

**どんなもの？**

検索エージェントが低品質な証拠に直面したときの頑健性を評価するため、検索モジュールを合成環境に置き換えるストレステスト枠組み DeepStress を提案した研究。クエリごとに動的生成される文書について、信頼性・関連性・事実性の3軸を独立に制御できる。最終回答を5分類で分析し、信頼性を考慮した新指標 RAS と CoPRAS も導入している。

**先行研究と比べてどこがすごい？**

従来は BrowseComp-Plus のように固定コーパスで検索器とLLMを切り分ける評価が中心で、頑健性の失敗は事後的にしか観察できず再現も難しかった。本研究は劣化の割合を実験者が制御でき、既存の敵対的環境の研究が攻撃を主眼とするのに対し、証拠品質の変化への反応を調べる点が異なる。また正誤の二値ではなく、棄権やツール予算超過などを含む5分類と、慎重な挙動に部分点を与える RAS/CoPRAS で評価する。

**技術や手法のキモはどこ？**

シナリオごとに信頼性(T)・関連性(R)・事実性(F)の確率を指定し、検索1回ごとに各軸の二値ラベルをサンプリングして、LLM (Gemma-4-31B) で1件の合成文書を生成する。事実的に正しい文書はデータセット付属の根拠文書に基づいて作り、誤り文書は重大な事実誤りを入れるよう指示する。低信頼文書は OpenSources の偽情報サイトのドメインを使い、無関係文書は別の質問の根拠文脈から生成する。RAS は正解に1、不正解・形式不備に0、棄権・ツール予算超過に 1-ρ（ρ は T・R・F の実現割合の積）を与え、CoPRAS はコストを RAS の総和で割った値である。

**どうやって有効だと検証した？**

GPT-5-nano/mini（各3段階の推論強度）、SpiqaDR、Search-R1、AutoRefine、ASearcher、DR-Tulu など12システムを、HotpotQA と BrowseComp-Plus 各200問、7シナリオ、合計33,600トレースで評価した。信頼性を0%にしても多くのシステムが棄権せず回答し、Search-R1 は正答率が78〜80%でほぼ変化しなかった。関連性・事実性の劣化では全システムの正答率が大きく低下し、Search-R1 の誤答率は19.5%から79.2%に上昇した。事実性0%でも HotpotQA は少なくとも10%、gpt-5-mini (medium) では60%が正解で、パラメトリック知識で答えている可能性が示唆された。BrowseComp-Plus はほぼ0に落ちた。人手検証（50件）では、ラベルとの一致率は信頼性96.4%、事実性85.5%だった。

**議論はある？**

検索1回につき文書1件で単一の検索ループという単純な設定であり、複数文書の混在や要約・リランキング・サブエージェントを持つ複雑なエージェントには直接当てはまらない可能性がある。合成文書は実Webより清潔で多様性が低く、3軸も独立にしか変化させていない。著者らは、狭い結果報酬のRLで訓練したモデルが脆いことを踏まえ、信頼性を考慮した訓練目的への応用を今後の方向として挙げている。

**次に読むべき論文は？**

- BrowseComp-Plus: A More Fair and Transparent Evaluation Benchmark of Deep-Research Agent：DeepStress が実験の土台にしている、固定コーパスで検索器とLLMを切り分ける評価ベンチマークである。
- Over-searching in Search-Augmented Large Language Models：TPC 指標とコスト定義の出典であり、ノイズのある検索条件で検索回数が増える現象を扱っている。
- DRAGged into Conflicts: Detecting and Addressing Conflicting Sources in Search-Augmented LLMs：RAG における知識衝突の分類と、各状況で期待される挙動を整理しており、事実性劣化の結果を解釈する助けになる。

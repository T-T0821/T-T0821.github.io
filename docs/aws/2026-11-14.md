今日は AWS のセキュリティ・ID 管理まわりの更新が目立ち、Secrets Manager のクロスアカウントレプリケーション、Security Hub CSPM と Organizations 宣言型ポリシーの連携、Cognito の OAuth 2.0 トークン交換、AgentCore Identity の OAuth 2.0 discovery URL 対応が発表されました。AI エージェントがユーザーに代わって下流サービスを呼ぶ場面を想定した認可まわりの拡充も続いています。データ基盤では Aurora/RDS の Graviton5 (R9g) 対応、Aurora PostgreSQL express configuration の CloudFormation 対応、RDS for Oracle のメンテナンス停止時間の短縮が出ています。アーキテクチャ記事ではエンタープライズ AI エージェントの参照構成や本番トラフィックを使ったリグレッションテストが紹介されています。

## ニュース

### AWS Secrets Manager がクロスアカウントレプリケーションに対応

[AWS Secrets Manager now supports cross-account replication](https://aws.amazon.com/about-aws/whats-new/2026/11/secrets-manager-cross-account/) ・ AWS What's New ・ 2026-11-13

プライマリシークレットのコピーを別の AWS アカウントに同期して保持できるようになりました。既存のマルチリージョンレプリケーションをアカウント境界を越えて拡張するもので、クロスアカウントアクセス、バックアップ、災害復旧に使えます。中央のチームがシークレットを管理・ローテーションし、利用側アカウントは常に最新のローカルコピーを参照できます。

**影響・使いどころ:** マルチアカウント構成でのシークレット配布や DR 設計を、共有 KMS キーなどに頼らず簡素化できる可能性があります。

### Security Hub CSPM が Organizations の宣言型ポリシーによる一元設定に対応

[AWS Security Hub CSPM now supports centralized configuration with AWS Organizations declarative policies](https://aws.amazon.com/about-aws/whats-new/2026/11/security-hub-cspm-org-policies/) ・ AWS What's New ・ 2026-11-13

宣言型ポリシーを使い、組織内の全アカウント・全リージョンで Security Hub CSPM を有効化し、有効にするセキュリティ標準やコントロールを定義できます。ポリシーは全体にも特定のアカウントとリージョンの組み合わせにも適用でき、設定のドリフト防止に役立ちます。

**影響・使いどころ:** 大規模組織での CSPM の展開と設定統制を、Organizations のポリシーとして一括管理できます。

### Amazon Cognito が OAuth 2.0 トークン交換（RFC 8693）に対応

[Amazon Cognito now supports OAuth 2.0 token exchange](https://aws.amazon.com/about-aws/whats-new/2026/11/cognito-token-exchange/) ・ AWS What's New ・ 2026-11-12

ユーザーに代わって動作するサービスや AI エージェントが、ユーザーのトークンを特定の下流サービス向けにスコープされた新しいトークンへ交換できるようになりました。従来は元のトークンを転送するか、独自にトークン発行の仕組みを構築・運用する必要がありました。

**影響・使いどころ:** マイクロサービスや AI エージェントの委任呼び出しで、トークンの最小権限化を標準仕様に沿って実装しやすくなります。

### Bedrock AgentCore Identity が OAuth 2.0 の discovery URL に対応

[Amazon Bedrock AgentCore Identity now supports OAuth 2.0 discovery URLs](https://aws.amazon.com/about-aws/whats-new/2026/11/bedrock-agentcore-oauth2-discovery/) ・ AWS What's New ・ 2026-11-13

インバウンドの JWT 認可とアウトバウンドの OAuth 認証情報プロバイダーの両方で、OAuth 2.0 認可サーバーの discovery URL を使えるようになりました。これまでは OIDC の discovery URL のみ対応で、OIDC 非対応の OAuth 2.0 サーバーは使えませんでした。

**影響・使いどころ:** OIDC を実装していない認可サーバーとも AgentCore を連携でき、接続可能な外部サービスの範囲が広がります。

### Aurora と RDS が Graviton5 ベースの R9g インスタンスに対応

[Amazon Aurora and RDS now support Graviton5-based R9g database instances](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-aurora-rds-postgresql-mysql-mariadb-r9g-instances/) ・ AWS What's New ・ 2026-11-12

Aurora (PostgreSQL 互換・MySQL 互換) と RDS for PostgreSQL / MySQL / MariaDB で R9g インスタンスが一般提供されました。Aurora では Graviton4 の同等サイズと比べ、オンデマンド料金で最大 30% の性能向上、最大 22% の価格性能比向上とされています（エンジン、バージョン、ワークロードによる）。

**影響・使いどころ:** 既存の Graviton4 インスタンスからの移行について、自社ワークロードでの検証を検討する価値があります。

### Aurora PostgreSQL の express configuration が CloudFormation に対応

[Aurora PostgreSQL with express configuration now supported in CloudFormation](https://aws.amazon.com/about-aws/whats-new/2026/11/aurora-postgresql-cloudformation/) ・ AWS What's New ・ 2026-11-13

express configuration で作成する Aurora PostgreSQL クラスターを CloudFormation テンプレートでデプロイできるようになりました。express configuration は Aurora Serverless データベースを数秒で作成してクエリできる構成で、createOnly プロパティ withExpressConfiguration を使って指定します。

**影響・使いどころ:** 検証環境や開発環境の Aurora を IaC で素早く用意でき、デプロイの自動化に組み込めます。

### RDS for Oracle がマイナーバージョン自動アップグレードとメンテナンスのダウンタイムを短縮

[Amazon RDS for Oracle reduces downtime for automatic minor version upgrades and scheduled maintenance](https://aws.amazon.com/about-aws/whats-new/2026/11/rds-oracle-reduces-maintenance-downtime-for-amvu-scheduled-upgrades/) ・ AWS What's New ・ 2026-11-13

自動マイナーバージョンアップグレードのほか、メンテナンスウィンドウで実施されるマイナーバージョンアップグレードと OS 更新でもダウンタイムが短縮されました。自動アップグレードを有効にしている DB インスタンスは自動的に恩恵を受けます。

**影響・使いどころ:** Oracle の最新マイナーバージョンや OS 更新への追従に伴うアプリケーションへの影響を抑えやすくなります。

### エンタープライズ AI エージェントの内部構成：統制と可観測性を備えたループ型アーキテクチャ

[Inside an enterprise AI agent: A governed, observable loop architecture](https://aws.amazon.com/blogs/architecture/inside-an-enterprise-ai-agent-a-governed-observable-loop-architecture/) ・ AWS Architecture Blog ・ 2026-11-12

API ゲートウェイ、5 フェーズのエージェントランタイム、知識・状態層、プラットフォームサービス、横断的な信頼・統制フレームワークからなる 5 層の参照アーキテクチャを紹介しています。各層を AWS のマネージドサービスに対応付け、参考にすべき設計パターンと避けるべき失敗例も扱っています。

**影響・使いどころ:** 社内で AI エージェント基盤を設計する際の、ガバナンスと可観測性を含む構成の検討材料になります。

## 📰 ニュース

### 1. AWS Secrets Manager がクロスアカウントレプリケーションに対応 {#news-1}

AWS What's New ・ 2026-11-13 ・ [原文を読む ↗](https://aws.amazon.com/about-aws/whats-new/2026/11/secrets-manager-cross-account/)

プライマリのシークレットを別の AWS アカウントに同期コピーとして維持でき、クロスアカウントアクセス、バックアップ、災害復旧に使えます。既存のマルチリージョンレプリケーションをアカウント境界の外へ拡張した機能です。プラットフォームチームやセキュリティチームが一元的にシークレットを管理・ローテーションし、各利用アカウントが常に最新のローカルコピーを持てる構成が可能になります。

::: tip 💡 影響・使いどころ
マルチアカウント環境でのシークレット配布や DR 設計が簡素化できる可能性があります。
:::

### 2. Security Hub CSPM が Organizations の宣言型ポリシーによる一元設定に対応 {#news-2}

AWS What's New ・ 2026-11-13 ・ [原文を読む ↗](https://aws.amazon.com/about-aws/whats-new/2026/11/security-hub-cspm-org-policies/)

AWS Organizations の宣言型ポリシーを使い、組織内の全アカウント・全リージョンで Security Hub CSPM を有効化し、有効にするセキュリティ基準やコントロールを定義できます。ポリシーはすべてのアカウントとリージョンへの適用も、特定のアカウントとリージョンの組み合わせへの適用も可能です。各アカウントの設定がポリシーと揃った状態に保たれ、構成のドリフトを防ぐのに役立ちます。

::: tip 💡 影響・使いどころ
組織全体のセキュリティ設定を一貫して管理したいチームにとって、運用負荷の軽減につながります。
:::

### 3. Amazon Cognito が OAuth 2.0 トークン交換（RFC 8693）に対応 {#news-3}

AWS What's New ・ 2026-11-12 ・ [原文を読む ↗](https://aws.amazon.com/about-aws/whats-new/2026/11/cognito-token-exchange/)

ユーザーに代わって動作するサービスや AI エージェントが、ユーザーのトークンを下流サービス向けにスコープされた新しいトークンに交換できるようになりました。従来は元のトークンを転送するか、独自にトークン発行の仕組みを構築・維持する必要がありました。

::: tip 💡 影響・使いどころ
AI エージェントやマイクロサービス間の委任認可で、元のトークンを使い回さない設計を採りやすくなります。
:::

### 4. Bedrock AgentCore Identity が OAuth 2.0 ディスカバリー URL に対応 {#news-4}

AWS What's New ・ 2026-11-13 ・ [原文を読む ↗](https://aws.amazon.com/about-aws/whats-new/2026/11/bedrock-agentcore-oauth2-discovery/)

インバウンドの JWT 認可とアウトバウンドの OAuth 認証情報プロバイダーの両方で、OAuth 2.0 の認可サーバーディスカバリー URL を指定できるようになりました。これまでは OIDC のディスカバリー URL のみ受け付けていたため、OIDC を使わない OAuth 2.0 認可サーバーは利用できませんでした。

::: tip 💡 影響・使いどころ
OIDC 非対応の認可サーバーを使う環境でも、AgentCore を既存の認証基盤と接続できるようになります。
:::

### 5. Aurora と RDS が Graviton5 ベースの R9g インスタンスに対応 {#news-5}

AWS What's New ・ 2026-11-12 ・ [原文を読む ↗](https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-aurora-rds-postgresql-mysql-mariadb-r9g-instances/)

Graviton5 ベースの R9g が、Aurora（PostgreSQL 互換・MySQL 互換）と RDS for PostgreSQL・MySQL・MariaDB で一般提供されました。Graviton4 ベースの同等サイズと比べ、Aurora ではオンデマンド料金で最大 30% の性能向上、最大 22% の価格性能比の向上があるとされています（エンジン、バージョン、ワークロードによる）。

::: tip 💡 影響・使いどころ
既存の Graviton4 インスタンスからの移行を、自社ワークロードで検証する価値があります。
:::

### 6. Aurora PostgreSQL の express configuration が CloudFormation に対応 {#news-6}

AWS What's New ・ 2026-11-13 ・ [原文を読む ↗](https://aws.amazon.com/about-aws/whats-new/2026/11/aurora-postgresql-cloudformation/)

express configuration で作成した Aurora PostgreSQL クラスターを、CloudFormation テンプレートでデプロイできるようになりました。express configuration は Aurora Serverless データベースを数秒で作成してクエリできる構成です。AWS::RDS::DBCluster に createOnly プロパティ withExpressConfiguration が追加されています。

::: tip 💡 影響・使いどころ
開発・検証用データベースの素早い払い出しを IaC で自動化できます。
:::

### 7. RDS for Oracle の自動マイナーバージョンアップグレードとメンテナンスのダウンタイムを短縮 {#news-7}

AWS What's New ・ 2026-11-13 ・ [原文を読む ↗](https://aws.amazon.com/about-aws/whats-new/2026/11/rds-oracle-reduces-maintenance-downtime-for-amvu-scheduled-upgrades/)

自動マイナーバージョンアップグレードに加え、メンテナンスウィンドウで実施するマイナーバージョンアップグレードと OS 更新のダウンタイムが短縮されました。自動マイナーバージョンアップグレードを有効にしている DB インスタンスは、自動的にこの改善の恩恵を受けます。

::: tip 💡 影響・使いどころ
Oracle の最新マイナーバージョンや OS 更新を、アプリへの影響を抑えて適用しやすくなります。
:::

### 8. AWS Batch on EKS が Linux capabilities、seccomp、Pod レベル設定に対応 {#news-8}

AWS What's New ・ 2026-11-13 ・ [原文を読む ↗](https://aws.amazon.com/about-aws/whats-new/2026/11/aws-batch-eks-security-context/)

EKS ジョブ定義で、Linux capabilities や seccomp プロファイル、Pod レベルの設定など、Kubernetes の securityContext の追加項目が使えるようになりました。Pod Security Standards の restricted プロファイルを適用している EKS クラスターでも、必要な権限とシステムコールだけでジョブを実行できます。設定は RegisterJobDefinition API で行います。

::: tip 💡 影響・使いどころ
restricted プロファイルを強制するクラスターで、最小権限の原則に沿って Batch ジョブを動かせます。
:::

## 📄 論文

### 1. 起動処理の共有と事前ウォームアップによるサーバーレス LLM のコールドスタート高速化 {#paper-1}

arXiv ・ Hongjin Kim, Igjae Kim, Kwanghoon Choi, Minho Ha ほか ・ [論文を読む ↗](https://arxiv.org/abs/2611.16180)

<small>原題: Fast Serverless LLM Cold Starts by Sharing and Prewarming Startup Work</small>

サーバーレス LLM のコールドスタートは約 1 分かかり、重みのロードはそのうち 5〜11% に過ぎず、大半はコンパイル、メモリプロファイリング、ランタイム設定が占めると指摘しています。提案手法 Cairn は、最初にモデルを起動したサーバーが重みとエンジンの成果物を、クラスター共有の CXL メモリプールに公開する仕組みです。

::: tip 🔍 注目ポイント
コールドスタートの主因が重みのロードではなく起動処理の重複にあるという分析が、サーバーレス推論基盤の設計に示唆を与えます。
:::

### 2. SBC クラスター上のエネルギー比例型サーバーレスコンピューティング {#paper-2}

arXiv ・ Yuliya Sasinskaya, Natalie Carl, Niklas Kowallik, David Bermbach ほか ・ [論文を読む ↗](https://arxiv.org/abs/2611.14026)

<small>原題: Energy-Proportional Serverless Computing on SBC Clusters</small>

サーバーレス関数の状態を持たない性質を利用し、スケールトゥゼロを関数インスタンスから物理ノードにまで広げて、エネルギー比例性を実現できると示しています。tinyFaaS を基にしたプラットフォームは、ノードの電源状態をワーカー選択の一部として扱います。

::: tip 🔍 注目ポイント
サーバーレスの省電力化をノードの電源管理まで含めて扱う点が、エッジやオンプレミス環境の運用を考える際の参考になります。
:::

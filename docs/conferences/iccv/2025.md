# ICCV 2025

👁️ 画像認識・CV ・ [ICCV の年ごとの流れ](./) ・ [公式サイト ↗](https://iccv.thecvf.com/)

::: info この回のまとめ
ホノルルで開催され、投稿11,152本・採択2,698本（約24.2%）でした。マー賞（Best Paper）は、テキストの指示から物理的に安定して実際に組み立てられるブロック構造を、LLM の次トークン予測で1個ずつ生成する BrickGPT（カーネギーメロン大学）です。生成中に物理法則と組み立て制約で不可能な配置を取り除き、ロボットによる組み立ても実演しました。最優秀学生論文は、学習済みのフローモデルを反転なしで使うテキスト画像編集 FlowEdit、佳作には場所ごとに焦点を変えられるオートフォーカスと、自己教師ありの大規模視点合成モデル RayZer が選ばれています。
:::

- **日程**: 2025年10月19日〜23日
- **開催地**: 米国・ホノルル
- **規模**: 投稿 11,152 本 ／ 採択 2,698 本 ／ 採択率 24.2%

**📝 注目論文（5 本）**

1. [BrickGPT：テキストから物理的に安定で組み立て可能なブロック構造を生成する](#paper-1)
2. [FlowEdit: 事前学習済みFlowモデルを用いた逆変換不要のテキストベース画像編集](#paper-2)

5. [Visual-RFT: 視覚強化ファインチューニング](#paper-5)

## 🔭 この回の主なテーマ

- 物理的に実現可能な生成: 安定性チェックと巻き戻しを組み込んだ自己回帰生成（BrickGPT）
- 生成モデルによる画像編集: 反転不要のフローモデル編集（FlowEdit）
- 計算光学: 画素ごとに焦点距離を変える空間可変オートフォーカス
- 自己教師ありの3D: 正解カメラ姿勢なしで学ぶ視点合成（RayZer）

::: tip 💡 技術動向への示唆
- 生成 AI に「物理的に作れるか」という制約を組み込む研究が最高賞を得ており、設計・製造向けの生成 AI（ジェネレーティブデザイン）への応用が近づいている
- 生成した設計をロボットが実際に組み立てるところまで示しており、生成 AI と製造の自動化がつながり始めている
:::

### 1. BrickGPT：テキストから物理的に安定で組み立て可能なブロック構造を生成する {#paper-1}

🏆 Best Paper（Marr Prize） ・ Ava Pun, Kangle Deng, Ruixuan Liu, Deva Ramanan ほか ・ [論文を読む ↗](https://arxiv.org/abs/2505.05469)

<small>原題: Generating Physically Stable and Buildable Brick Structures from Text</small>

物理的に安定なブロック構造と説明文の大規模データセットを作り、次に置くブロックを LLM に予測させます。推論中に物理法則と組み立て制約で不可能な候補を除き、崩れる場合は巻き戻すことで、人やロボットが実際に組み立てられる設計を生成しました。

::: info 📝 落合フォーマット

**どんなもの？**

テキストプロンプトから、物理的に安定で実際に組み立て可能なインターロッキング玩具ブロック（LEGO等）構造を生成する初の手法BrickGPTを提案した研究。あわせて、47,000以上のブロック構造（28,000以上のユニークな3Dオブジェクト）とキャプションを含むデータセットStableText2Brickを構築・公開した。生成物は人手およびロボットアームによる組み立てが可能で、テキストによる着色・テクスチャ付与も扱う。

**先行研究と比べてどこがすごい？**

既存のブロック生成研究は入力3D形状が必要、または単一カテゴリに限定されていたが、本研究は自由なテキストから多様なカテゴリのブロック構造を直接生成する。LLMの次トークン予測を「次のブロック予測」に転用し、推論時に物理安定性の検証とロールバックを組み込む点が新しい。本文によれば、物理を考慮したテキスト駆動のブロック構造生成としては初の試みである。

**技術や手法のキモはどこ？**

各ブロックを「&#123;h}×&#123;w} (&#123;x},&#123;y},&#123;z})」というテキスト形式で表現し、下から上へのラスタ順に並べたシーケンスで、LLaMA-3.2-1B-Instructを指示形式（Create a LEGO model of &#123;caption}.）でファインタジューニングする。データはShapeNetCoreのメッシュを20×20×20のグリッドにボクセル化し、delete-and-rebuild法で複数のレイアウトを作成、StableLegoの静的平衡に基づく非線形計画（Gurobi）で安定性スコアを算出して安定な構造のみ採用、キャプションはGPT-4oで生成した。推論時は、書式・ライブラリ内・範囲内・衝突なしを確認するブロック単位の棄却サンプリングを行い、完成後に安定性を検証して不安定なら最初の不安定ブロック以降を削除して生成を再開する（物理認識ロールバック）。着色はFlashTexによるUVテクスチャ生成と、標準色ライブラリへの一様な色割り当てに対応する。

**どうやって有効だと検証した？**

検証データから無作為に選んだ250プロンプトで、LLaMA-Mesh、LGM、XCube、Hunyuan3D-2（メッシュをブロック化）や事前学習LLaMA（0-shot/5-shot）と比較し、有効率・安定率・安定性スコア・CLIP・DINOv2で評価した。BrickGPTは有効率100%・安定率98.8%（平均安定性0.996、最小0.915）で、最良のベースラインであるHunyuan3D-2＋安定性解析の88.4%を上回り、CLIPは0.324と同等水準を保った。ロールバックなしでは安定率24.0%、棄却サンプリングもなしでは有効率37.2%・安定率12.8%に低下し、各構成要素の寄与を確認した。1構造の生成時間の中央値は40.8秒、ロールバック回数の中央値は2回である。

**議論はある？**

データは21カテゴリのShapeNetCore由来で、20×20×20のグリッドと1単位高のブロックに制約されており、より大規模・多様な構造への一般化は本文の範囲では示されていない。生成の途中段階ではなく完成後にのみ安定性を検証するため、ロールバックの反復に起因する推論コストが生じ得る（中央値40.8秒）。また、色情報を除いて学習しており、テクスチャは後処理に依存している。

**次に読むべき論文は？**

- StableLego: Stability analysis of block stacking assembly：本研究のデータ選別と推論時の安定性検証の基盤となる、ブロック構造の力学的安定性解析手法を理解できる。
- LLaMA-Mesh: Unifying 3D Mesh Generation with Language Models：LLMで3D形状をプレーンテキストとして生成する直接の先行手法であり、主要ベースラインでもある。
- Legolization: optimizing LEGO designs：delete-and-rebuild法によるブロックレイアウト生成と安定性を考慮した設計の原典として、データ構築部分の理解に役立つ。

:::


### 2. FlowEdit: 事前学習済みFlowモデルを用いた逆変換不要のテキストベース画像編集 {#paper-2}

🏆 Best Student Paper ・ Vladimir Kulikov, Matan Kleiner, Inbar Huberman-Spiegelglas, Tomer Michaeli ・ [論文を読む ↗](https://arxiv.org/abs/2412.08629)

<small>原題: FlowEdit: Inversion-Free Text-Based Editing Using Pre-Trained Flow Models</small>

SD3やFLUXなど事前学習済みの生成フローモデルを使い、逆変換・最適化・モデル内部への介入なしに、実画像をテキストプロンプトで編集する手法FlowEditを提案した研究です。ガウスノイズを経由せずソースからターゲットへ直接ODEパスを構成することで輸送コストを下げ、構造保存を高めており、SD3で生成した猫画像1000枚を犬へ編集する実験でも逆変換よりMSE・LPIPS・FID・KIDが良好でした。SDEditやRF-Inversionなどとの比較でCLIPとLPIPSの両立に優れ、モデルに依存せず適用できる点が評価され、ICCV 2025でBest Student Paperを受賞しています。

::: info 📝 落合フォーマット

**どんなもの？**

事前学習済みのテキストから画像への生成フローモデル（SD3、FLUX）を用いて、実画像をテキストプロンプトで編集する手法FlowEdit を提案した研究。逆変換（inversion）も最適化もモデル内部への介入も不要で、モデルに依存せず適用できる。

**先行研究と比べてどこがすごい？**

従来の「画像→ノイズ→編集画像」という逆変換ベースの編集を、ソース分布からターゲット分布への直接パスとして再解釈した。そのうえで、ガウスノイズを経由しないより短い直接ODEパスを構成し、輸送コストを下げて構造保存を高めた。注意マップ注入のようなアーキテクチャ依存の工夫を必要としない点も優れている。

**技術や手法のキモはどこ？**

ソース画像から、独立なガウス過程 N_t を用いて (1−t)Z0src + tN_t というノイズ付きソースを作り、Z_tar = Z_FE + Z_src − X_src としてターゲット側の点を得る。ソース・ターゲット各プロンプト条件の速度の差 V^Δ = V_tar − V_src を計算し、これをODEの更新方向として Z_FE を t=1 から 0 へ進める。実際には同じノイズでソースとターゲットの速度を計算し、n_avg 回の平均で期待値を近似する。開始ステップ n_max で編集の強さを調整する。

**どうやって有効だと検証した？**

SD3で生成した猫画像1000枚を犬へ編集する実験では、FlowEditは逆変換より輸送コストが低く（MSE 1376 vs 2239、LPIPS 0.15 vs 0.25）、FID（51.14 vs 55.88）とKID（0.017 vs 0.023）も良好だった。70枚超の実画像と250組超のテキスト画像ペアで、SDEdit、iRFDS、RF-Inversion、RF Editなどと比較した。CLIP（テキスト適合）とLPIPS（構造保存）の両立で優れており、定性的にも構造保存とプロンプト適合を両立できていた。

**議論はある？**

構造保存が強いため、ポーズや背景など画像の大きな領域を大幅に変える編集には向かないという限界がある。手法はヒューリスティックであり、ターゲット分布への正確な写像や最適輸送との一致は保証されない。

**次に読むべき論文は？**

- Delta Denoising Score：FlowEditと表面的に似た最適化ベース編集手法であり、本論文が両者の違いを論じているため。
- An Edit Friendly DDPM Noise Space: Inversion and Manipulations：正確なノイズ既知でも逆変換編集が構造を保てない問題を指摘した、本研究の動機となる先行研究のため。
- Semantic Image Inversion and Editing using Rectified Stochastic Differential Equations：フローモデル向けの逆変換ベース編集手法（RF-Inversion）で、本論文の主要な比較対象のため。

:::


### 3. RayZer: 自己教師あり大規模視点合成モデル {#paper-3}

🏆 Best Paper Honorable Mention ・ Hanwen Jiang, Hao Tan, Peng Wang, Haian Jin ほか ・ [論文を読む ↗](https://arxiv.org/abs/2505.00702)

<small>原題: RayZer: A Self-supervised Large View Synthesis Model</small>

カメラポーズや3D形状といった3D教師なしで学習し、ポーズ未知の画像からカメラ推定・シーン再構成・新規視点合成をフィードフォワードで行う自己教師ありモデルを提案した研究である。自身が予測したポーズで目標視点をレンダリングし2D光度損失のみで学習する点が特徴で、DL3DVとRealEstateではポーズラベルを使うLVSMを上回るPSNRを示した（完全なGTポーズを持つObjaverseではやや劣る）。ICCV 2025でBest Paper Honorable Mentionを受賞している。

::: info 📝 落合フォーマット

**どんなもの？**

RayZerは、カメラポーズや3D形状といった3D教師なしで学習される自己教師あり大規模マルチビュー3Dモデルである。ポーズ・キャリブレーション未知の画像から、カメラパラメータの推定、シーン表現の再構成、新規視点合成をフィードフォワードで行う。

**先行研究と比べてどこがすごい？**

学習時にGTではなく自身が予測したカメラポーズで目標視点をレンダリングし、2Dの光度損失のみで学習する点が新しい。ポーズ推定を先に行い、その結果でシーン再構成を条件づける「ポーズ先行」の設計と、純粋なTransformerでレイ構造のみを3D事前知識とする点で、潜在ポーズを用いシーン再構成を先に行うRUSTなどと異なる。

**技術や手法のキモはどこ？**

入力画像を、シーン表現を予測するセットAと、教師信号を与えるセットBに分割し、情報の流れを制御して自明解を防ぐ。カメラ推定器が相対SE(3)ポーズ（6D回転表現）と焦点距離を予測し、Plücker光線マップに変換する。シーン再構成器は、セットAの画像トークンと光線マップを融合して潜在トークン集合を作り、LVSM型のレンダリングデコーダがセットBの予測光線から画像を生成して、MSEと知覚損失で学習する。各モジュールは8層のTransformerである。

**どうやって有効だと検証した？**

DL3DV、RealEstate、Objaverseの3データセットで新規視点合成を評価し、GS-LRMやLVSMなど姿勢ラベルを使う「oracle」手法と比較した。DL3DVではPSNR 24.36でLVSMの23.69を上回り、RealEstateでも27.48でLVSMの27.00を上回った。一方、完全なGTポーズを持つObjaverseではLVSMの32.34に対しRayZerは31.52とやや劣る。著者らは、COLMAP由来のポーズが不完全なことがoracle手法の上限になっていると推測している。アブレーションでは、3DGS表現では学習が収束せず、Plücker光線の除去やシーン先行の順序では性能が低下した。

**議論はある？**

順序なし画像集合での学習は、連続動画フレームでの学習よりも性能が低く（DL3DVでPSNR 20.56対24.36）、動画由来のデータが有利とされる。学習されるポーズ空間は実世界のポーズ空間と厳密には一致せず、評価も予測ポーズで行う必要がある。焦点距離を全ビュー共通の単一値とし、主点を画像中心とするなどの仮定、および静的シーンに限られる点も制約である。なお、COLMAPのノイズがoracle手法の限界だという説明は、著者による推測（conjecture）である。

**次に読むべき論文は？**

- LVSM: A Large View Synthesis Model with Minimal 3D Inductive Bias：RayZerのレンダリングデコーダと主要な比較対象となっており、潜在集合表現による新規視点合成の基盤を理解できる。
- RUST: Really Unposed Scene representation Transformer：未ポーズ画像から潜在シーン表現を自己教師ありで学習する最も関連の深い先行研究で、RayZerとの設計差を確認できる。
- PF-LRM: Pose-Free Large Reconstruction Model for Joint Pose and Shape Prediction：カメラ教師を用いてポーズ推定と再構成を同時に行う教師あり手法で、RayZerの比較対象として違いを理解できる。

:::


### 4. LLaVA-CoT: 視覚言語モデルに段階的な推論をさせる {#paper-4}

📈 被引用数上位（Paper Digest の集計で同年1位） ・ Guowei Xu, Peng Jin, Ziang Wu, Hao Li ほか ・ [論文を読む ↗](https://arxiv.org/abs/2411.10440)

<small>原題: LLaVA-CoT: Let Vision Language Models Reason Step-by-Step</small>

視覚言語モデルが複雑な視覚質問応答で体系的な推論を苦手とする問題に対し、要約・画像記述・推論・結論の4段階をタグで明示し、モデル自身が単一の推論パスで進める LLaVA-CoT を、10万件規模のデータ LLaVA-CoT-100k で学習させた研究です。ステージ単位ビームサーチに、報酬が閾値を超えない場合に前段階へ戻るリトレーシング機構を加えた推論時スケーリング手法 SWIRES も提案し、6ベンチマークの平均でベースモデルの56.6から62.4、SWIRES適用で65.5へ向上しました。推論重視のベンチマークでは Llama-3.2-90B-Vision-Instruct、Gemini-1.5-Pro、GPT-4o-mini を上回っており、ICCV 2025 で Paper Digest 集計の被引用数が同年1位である点も注目されます。

::: info 📝 落合フォーマット

**どんなもの？**

視覚言語モデル（VLM）が複雑な視覚質問応答で体系的・構造的な推論をできない問題に対し、自律的に多段階推論を行うVLM「LLaVA-CoT」を提案した研究。要約・画像記述・推論・結論の4段階を自ら進めるよう、10万件規模のデータ（LLaVA-CoT-100k）で学習する。さらに推論時スケーリング手法SWIRESも提案している。

**先行研究と比べてどこがすごい？**

単なるCoTプロンプトではなく、4段階をタグで明示した構造化推論をモデル自身が単一の推論パスで自発的に実行する点が新しい。また、固定間隔ではなく推論ステージ単位で探索を行うステージ単位ビームサーチに、報酬が閾値を超えない場合に前段階へ戻って再生成するリトレーシング機構を加えた点が先行のbest-of-Nやビームサーチと異なる。

**技術や手法のキモはどこ？**

VQAデータセット10種から集めた約99k件に対しGPT-4oで&lt;SUMMARY>/&lt;CAPTION>/&lt;REASONING>/&lt;CONCLUSION>の4段階の推論応答を生成・フィルタし、Llama-3.2-11B-Vision-Instructを全パラメータSFTする。推論時は各ステージでM個の候補を生成して報酬モデル（InternLM-XComposer2.5-Reward）で上位N個を残す。全候補が閾値未満なら前ステージに戻って再生成し、最大C回まで繰り返す（SWIRES）。caption段階以降に適用する。

**どうやって有効だと検証した？**

MMStar、MMBench V1.1、MMVet、MathVista、AI2D、HallusionBenchの6ベンチマークで評価し、ベースモデルの平均56.6に対しLLaVA-CoTは62.4、SWIRESによるスケーリング適用で65.5となった。元のQ&Aで直接学習した場合（59.0）やタグなしの場合（60.9）より高く、MMStarでは推論系スキルの向上が大きかった。推論重視に絞ったベンチマークの比較では、Llama-3.2-90B-Vision-Instruct、Gemini-1.5-Pro、GPT-4o-miniを上回る結果を示した。

**議論はある？**

学習データがGPT-4o生成の応答に依存しており、品質や教師モデルへの依存が課題になりうる。また、スケーリング効果の比較は主にMMStarで示されており、探索による計算コストの増大も考慮が必要である。今後の展望として、強化学習による複雑なマルチモーダル推論のさらなる改善が挙げられている。

**次に読むべき論文は？**

- Visual CoT: Advancing Multi-Modal Language Models with a Comprehensive Dataset and Benchmark for Chain-of-Thought Reasoning：VLMにCoT応答を学習させる関連手法であり、本論文の構造化CoTとの違いを比較するために有用。

### 5. Visual-RFT: 視覚強化ファインチューニング {#paper-5}

📈 被引用数上位（Paper Digest の集計で同年2位） ・ Ziyu Liu, Zeyi Sun, Yuhang Zang, Xiaoyi Dong ほか ・ [論文を読む ↗](https://arxiv.org/abs/2503.01785)

<small>原題: Visual-RFT: Visual Reinforcement Fine-Tuning</small>

OpenAI o1やDeepSeek-R1で注目された検証可能な報酬による強化学習ファインチューニングを、数学・コード以外の視覚認識タスクへ拡張し、IoU報酬や分類報酬といったルールベースの報酬でLVLMを更新するVisual-RFTを提案した研究です。Qwen2-VL-2Bの細粒度分類1-shotで平均精度が56.0から80.3に向上し、SFTは51.7に低下したほか、COCOやLVISの検出、LISAの推論グラウンディングでもSFTを上回っています。少量データでも報酬設計によってデータ効率を高められる点が評価され、ICCV 2025で被引用数が同年2位(Paper Digest集計)となっています。

::: info 📝 落合フォーマット

**どんなもの？**

OpenAI o1やDeepSeek-R1で注目された検証可能な報酬による強化学習ファインチューニング（RFT）を、数学・コード以外の視覚認識タスクへ拡張するVisual-RFTを提案した研究。大規模視覚言語モデル（LVLM）に推論過程と最終回答を生成させ、タスク別の報酬で更新することで、少量データでも細粒度分類・物体検出・推論グラウンディングなどの性能を高める。

**先行研究と比べてどこがすごい？**

従来RFT/RLVRは数学やコードなど正解が明確な領域が中心で、LVLMへの適用は幻覚低減や人間の嗜好アライメントにとどまっていた。本研究は視覚認識タスク向けにルールベースの検証可能報酬（IoU報酬、分類報酬）を設計し、GRPO系の強化学習をLVLMの視覚知覚・グラウンディング強化に適用した点が新しい。正解の模倣であるSFTと異なり、データ量を増やすのではなく報酬設計でデータ効率を高める枠組みである。

**技術や手法のキモはどこ？**

各入力に対しポリシーモデル（Qwen2-VL-2B/7B）が&lt;think>推論&lt;/think>と&lt;answer>回答&lt;/answer>形式で複数の応答を生成し、検証可能報酬で採点する。GRPOでは報酬をグループ内で平均・標準偏差により正規化して相対的な優位度を求め、critic不要で更新し、KL項で参照モデルとの乖離を抑える。検出タスクの報酬は、IoU報酬（出力ボックスの平均IoU）、信頼度報酬（IoUが0でない一致ボックスは高信頼度ほど、不一致ボックスは低信頼度ほど高報酬）、形式報酬の和である。分類タスクは正解なら1となる精度報酬と形式報酬の和である。

**どうやって有効だと検証した？**

Qwen2-VL-2Bの細粒度分類（Flower102、Pets37、FGVC-Aircraft、Cars196）の1-shotで平均精度がベースライン56.0から80.3（+24.3）に向上し、SFTは51.7に低下した。COCOの8カテゴリ2-shotでmAPが+21.9、LVISの希少6カテゴリ（10-shot相当）で+15.4となり、SFTを上回った。LISAの推論グラウンディング（学習画像239枚）では2Bでmean IoU（test）が37.6でSFTの28.3を上回り、COCOの65基本カテゴリで学習したオープンボキャブラリ検出では新規15カテゴリのmAPが9.8から31.3、LVIS希少カテゴリで2.7から20.7に改善した。

**議論はある？**

検証は主にQwen2-VLの2B/7Bに限られ、評価もタスクごとの少量データ設定が中心である。7Bでは改善幅が2Bより小さい傾向があり（例: LISAのmean IoU test +3.5）、モデル規模や他のLVLMでの一般性は本文からは確認できない。報酬はタスクごとに手作業で設計する必要があり、正解が明確に定義しにくいタスクへの拡張が課題である。

**次に読むべき論文は？**

- DeepSeek-R1: Incentivizing reasoning capability in llms via reinforcement learning：Visual-RFTの土台となる検証可能報酬とGRPOによる強化学習の考え方を理解できる。
- DeepSeekMath: Pushing the limits of mathematical reasoning in open language models：本手法が採用するGRPOアルゴリズムの原典である。
- Qwen2-VL: Enhancing vision-language model's perception of the world at any resolution：Visual-RFTで実験に用いられたベースLVLMの構造と能力を把握できる。

# ACL 2025

💬 自然言語処理 ・ [ACL の年ごとの流れ](./) ・ [公式サイト ↗](https://www.aclweb.org/)

::: info この回のまとめ
2025年7月27日〜8月1日にオーストリアのウィーンで開催されました。投稿は8,360本と前年のほぼ2倍に増え、本会議に1,699本（20.3%）、Findings に1,392本（16.7%）が採択されています。第一著者の国・地域の51.3%を中国が占め、前年の30.6%から急増しました。最優秀論文は4本で、GPU に合わせて設計し学習時から使える疎なアテンション（DeepSeek・北京大学）、LLM がアラインメント後も事前学習時の振る舞いに戻ろうとする「弾性」の研究（北京大学）、LLM の応答のサンプリングが規範的な理想に引っ張られることを示した理論、集団間の違いを認識すべき場面での公平性の測定でした。
:::

- **日程**: 2025年7月27日〜8月1日

## 📝 注目論文

### 1. ネイティブ疎アテンション: ハードウェアに合わせた、学習時から使える疎なアテンション {#paper-1}

🏆 Best Paper ・ Jingyang Yuan, Huazuo Gao, Damai Dai, Junyu Luo ・ [論文を読む ↗](https://arxiv.org/abs/2502.11089)

<small>原題: Native Sparse Attention: Hardware-Aligned and Natively Trainable Sparse Attention</small>

粗い圧縮・重要ブロックの選択・近傍の窓という3つの経路を組み合わせ、GPU で効率よく動く疎なアテンションを事前学習から使えるようにしました。長文脈で密なアテンションと同等以上の性能を保ちつつ、学習と推論を大幅に高速化しました。

::: info 📝 落合フォーマット

**どんなもの？**

長文脈モデリングにおける標準Attentionの計算コストを下げるため、学習時から使えるスパースAttention機構「NSA（Natively trainable Sparse Attention）」を提案した研究。アルゴリズム設計とハードウェアに整合したカーネル実装を組み合わせ、事前学習から推論（prefill/decoding）まで一貫して効率化することを目指している。

**先行研究と比べてどこがすごい？**

既存のスパースAttentionは推論時のみに適用されることが多く、prefillとdecodingの片方しか高速化できない、GQA/MQAと相性が悪い、選択操作が微分不可能で学習できない、といった課題があった。NSAは階層的スパース構造をエンドツーエンドで学習可能にし、GQAグループ単位のブロック選択とArithmetic Intensityを考慮したカーネル設計で、理論上の削減を実際の高速化につなげている点が新しい。

**技術や手法のキモはどこ？**

各クエリに対し、(1)ブロック圧縮（学習可能なMLPでキー・バリューをブロック単位に圧縮）、(2)選択（圧縮Attentionのスコアからブロック重要度を導出し、上位nブロックの細粒度トークンを保持）、(3)スライディングウィンドウ（局所文脈）の3経路でAttentionを計算し、MLPとsigmoidによるゲートで統合する。局所パターンによるショートカット学習を防ぐため、3経路に独立したキー・バリューを与える。GQAグループ内のヘッドでブロック選択を共有し、グループ単位でクエリをSRAMへロードするTritonカーネルを実装して、KV転送の重複を排除し連続メモリアクセスを実現している。

**どうやって有効だと検証した？**

27B（アクティブ3B）のGQA+MoEモデルを260B〜270Bトークンで事前学習し、Full Attentionと比較した。一般ベンチマークでは9指標中7指標でFull Attentionを上回り（平均0.456 vs 0.443）、LongBenchの平均は0.469でFull Attentionを+0.032、Exact-Topを+0.046上回り、64kのNeedle-in-a-Haystackでは全位置で完全な検索精度を示した。AIME 24（DeepSeek-R1蒸留SFT後）では8k生成で0.121 vs 0.046、16kで0.146 vs 0.092。速度面では64k長でFlashAttention-2比で順伝播最大9.0倍、逆伝播最大6.0倍、decodingでは最大11.6倍の期待高速化を示した。

**議論はある？**

検証はA100上のTriton実装と単一スケール（27Bモデル）が中心であり、decodingの高速化はメモリアクセス量に基づく期待値である。他のスケール、アーキテクチャ、ハードウェアでの再現性は本文からは確認できない。また、ブロック間の注意パターンがなぜブロック状にクラスタ化するかについては、著者自身が詳細な調査が必要としている。

**次に読むべき論文は？**

- SeerAttention: Learning Intrinsic Sparse Attention in Your LLMs：補助損失でブロック重要度を学習する関連手法で、NSAが比較・批判した選択戦略との違いを理解できる。
- Quest: Query-Aware Sparsity for Efficient Long-Context LLM Inference：ブロック単位のクエリ依存KV選択の代表的ベースラインで、GQAとの非互換性などNSAが指摘した課題の背景を把握できる。
- H2O: Heavy-Hitter Oracle for Efficient Generative Inference of Large Language Models：KVキャッシュ削除型スパース化の代表例で、NSAが対象とするphase-restricted sparsityの問題を理解するのに役立つ。

:::


### 2. 言語モデルはアラインメントに抵抗する: データ圧縮からの証拠 {#paper-2}

🏆 Best Paper ・ Jiaming Ji, Kaile Wang, Tianyi Qiu, Boyuan Chen ほか ・ [論文を読む ↗](https://arxiv.org/abs/2406.06144)

<small>原題: Language Models Resist Alignment: Evidence From Data Compression</small>

アラインメント済みのモデルが少量の追加学習で事前学習時の振る舞いに戻りやすい「弾性」を、圧縮の理論と実験で示しました。モデルが大きく事前学習データが多いほど戻りやすく、安全対策の設計に課題を投げかけました。

::: info 📝 落合フォーマット

**どんなもの？**

アライメント済みLLMが追加のファインチューニングで容易に事前学習時の挙動分布へ戻ってしまう現象を「弾性（elasticity）」と名付け、圧縮理論に基づいて理論的・実証的に示した研究。弾性が、モデルがアライメントに抵抗する（resistance）ことや、アライメントを元に戻す逆アライメント（inverse alignment）が可能になることの原因であると主張している。

**先行研究と比べてどこがすごい？**

アライメントの脆弱性を、LLMを可逆圧縮プロトコルとみなす圧縮理論の枠組みで説明しようとした初の試みと位置づけている。複数データセットに対する正規化圧縮率の変化がデータ量に反比例する（直列バネのフックの法則に類似）という不変量を導出し、事前学習データとアライメントデータの規模差から、アライメントが桁違いに崩れやすいことを示した点が新しい。

**技術や手法のキモはどこ？**

LLMを、トークン木を深さdで剪定しハフマン符号化する可逆圧縮プロトコルとしてモデル化し（モデルサイズが大きいほど扱える木の深さが増すと仮定）、圧縮率を学習損失の代理指標とする。事前学習データD_p、アライメントデータD_a、摂動データD_tを合わせて圧縮する状況で、各データがパレート質量分布に従うと仮定し、摂動量に対する正規化圧縮率の変化率がデータ量に反比例することを定理4.2として導出した。これをバネ定数と伸びの関係に対応づけ、弾性を F ∝ |D_i|·ΔD_KL として定式化している。

**どうやって有効だと検証した？**

抵抗性の検証では、Llama2-7B/13B、Llama3-8Bを Alpaca・TruthfulQA・Beavertails でSFTしたスライス間で、逆向きの学習損失が順向きより一貫して低いことを確認した（例：Alpaca・Llama2-7Bで0.1589対0.2018）。反発（rebound）の検証では、Llama2-7BとGemma-2BをIMDbとBeavertailsで学習し、正例データが多いモデルほど少量の負例ファインチューニングで性能が急落し、その後は低下が緩やかになることを示した。また Qwen（0.5B/4B/7B）やTinyLlama（事前学習2.0T/2.5T/3.0T）の実験で、モデルサイズと事前学習データ量が増えるほど反発が強まる傾向を確認した。

**議論はある？**

理論面ではデータの質量分布（パレート分布）の仮定が主な限界で、その実際の形を調べる実証研究が必要とされている。実験面では事前学習とアライメントの全ライフサイクルにわたる検証はコスト上できておらず、マルチモーダルモデルへの適用やスケーリング則との関係解明が今後の課題である。また、逆アライメントによるオープンソースモデルの安全性低下を防ぐため、ファインチューニング耐性のある頑健なアライメント手法が求められると論じている。

**次に読むべき論文は？**

- Safety Alignment Should Be Made More Than Just a Few Tokens Deep：本文で言及されている浅い安全性アライメント（shallow safety alignment）の概念を扱っており、アライメントの脆さの別の説明として本研究と比較できる。
- Language Modeling Is Compression：本研究の理論的基盤である、言語モデルの予測と可逆圧縮の等価性を示した論文である。
- Alignment Faking in Large Language Models：モデルが学習目的に選択的に従い元の選好を保とうとする現象を扱っており、本研究の抵抗性の議論と関連が深い。

:::

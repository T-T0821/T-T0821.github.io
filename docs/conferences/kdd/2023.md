# KDD 2023

🔎 データマイニング・Web ・ [KDD の年ごとの流れ](./) ・ [公式サイト ↗](https://kdd.org/)

- グラフのプロンプト学習: 事前学習済み GNN を多様なタスクに転用する

:::

### 1. All in One: グラフニューラルネットワークのためのマルチタスク・プロンプト {#paper-1}

🏆 Best Paper（研究トラック） ・ Xiangguo Sun, Hong Cheng, Jia Li, Bo Liu ほか ・ [論文を読む ↗](https://arxiv.org/abs/2307.01504)

<small>原題: All in One: Multi-task Prompting for Graph Neural Networks</small>

グラフの事前学習は、ノード・エッジ・グラフ単位とタスクの種類が多様なため、下流タスクで逆効果（負の転移）になることがありました。タスクをグラフ単位の形式にそろえ、学習可能な「プロンプトグラフ」で事前学習モデルとタスクの溝を埋める方法を示しました。

::: info 📝 落合フォーマット

**どんなもの？**

グラフのノード・エッジ・グラフレベルの多様なタスクに対し、事前学習済みGNNを凍結したまま、軽量なプロンプトグラフで下流タスクを事前学習の形式に合わせるマルチタスク・プロンプト手法（All in One）を提案した研究。NLPのプロンプト学習の考えをグラフに導入し、事前学習と下流タスクのギャップや負の転移を緩和することを目指す。

**先行研究と比べてどこがすごい？**

従来のグラフプロンプト研究GPPTはノード分類のみ、かつエッジ予測を事前学習に限定していたが、本手法はノード・エッジ・グラフの各タスクに対応し、GraphCLやSimGRACEなどのグラフレベル事前学習とも互換性がある。また、プロンプトをトークン・トークン構造・挿入パターンの3要素で定義してNLPとグラフのプロンプトを統一的に扱い、メタ学習でプロンプトの初期化を学習する点が新しい。

**技術や手法のキモはどこ？**

ノード・エッジのタスクを、対象ノードや対象ノード対のτ-ego（誘導部分）グラフを作ってそのラベルを付与することで、グラフレベルのタスクに再定式化する。プロンプトグラフG_p=(P,S)は学習可能なトークン、トークン間構造（学習パラメータ・内積による枝刈り・独立の3方式）、挿入パターン（トークンと入力ノード特徴の内積による重み付き加算）からなり、入力ノード特徴に加算して凍結済み事前学習モデルに入力する。さらに、ノード・エッジ・グラフ分類を混ぜたマルチタスクのエピソードでMAML型メタ学習（内側で適応、外側で二次勾配更新）を行い、プロンプトとタスクヘッドの初期値を学習する。タスクヘッドなしで、ノードクラスごとのサブプロンプトで生成したビューのうち誘導グラフに最も近いものでクラスを決める方式も示している。

**どうやって有効だと検証した？**

Cora、CiteSeer、Reddit、Amazon、Pubmedの5データセットで、教師あり（GAT/GCN/GT）、事前学習＋ファインチューニング（GraphCL/SimGRACE）、プロンプトの3方式を、各クラス100サンプルのfew-shot設定でAcc・F1・AUCにより比較した。事前学習＋ファインチューニングに対する改善は、ノードレベルで1.10%〜8.81%、エッジレベルで1.28%〜12.26%、グラフレベルで0.14%〜10.77%と報告されている。ノード分類ではラベル比率50%のGPPTの報告値より少ないラベル量（約1.5〜25%）でも比較している。付録ではマルチクラス設定（Cora/CiteSeer）や回帰・リンク予測などの追加実験も行っている。

**議論はある？**

提供された本文は転移性分析（RQ2）以降が途中で省略されており、転移性、アブレーション、効率性の実験結果は確認できない。理論的な柔軟性の議論はFang et al.の結果に依存しており、誤差上界O_pφはモデルの非線形層にも左右される。また、二次勾配を用いるメタ学習の計算コストや、グラフレベル事前学習への依存、誘導グラフ化の設計が性能に与える影響は議論の余地がある。

**次に読むべき論文は？**

- GPPT: Graph pre-training and prompt tuning to generalize graph neural networks：本論文が直接の比較対象かつ特殊ケースと位置づける先行のグラフプロンプト手法で、差分を理解するのに必須である。
- Prompt Tuning for Graph Neural Networks：プロンプトトークンで任意のグラフ操作を模倣できるという、本論文の柔軟性の議論の根拠となる理論を扱っている。
- Graph contrastive learning with augmentations (GraphCL)：本論文が標準の事前学習戦略として使うグラフレベル対照学習の基盤となる手法である。

:::


### 2. 推薦システムにおけるマルチタスク・ランキングモデルの学習安定化 {#paper-2}

🏆 Best Paper（ADS トラック） ・ Jiaxi Tang, Yoel Drori, Daryl Chang, Maheswaran Sathiamoorthy ・ [論文を読む ↗](https://arxiv.org/abs/2302.09178)

<small>原題: Improving Training Stability for Multitask Ranking Models in Recommender Systems</small>

実運用の大規模な推薦モデルで起きる学習の発散（損失の急上昇）の原因を分析し、最適化手法の改良で安定させました。研究論文では扱われにくい、実際の製品で起きる問題に正面から取り組んだ点が評価されました。

::: info 📝 落合フォーマット

**どんなもの？**

YouTubeの実運用マルチタスクランキングモデルで頻発する学習不安定性（損失発散）の原因を整理し、その対策として新しい最適化手法Clippyを提案した研究。大きな学習率やモデル容量増大でも収束を損なわずに学習を安定させることを目指している。実装はTensorFlow Recommendersで公開されている。

**先行研究と比べてどこがすごい？**

レコメンドモデルの学習安定性という未開拓の課題に対し、データ分布の変化、モデルの大規模化・複雑化、複数目的による共有層の不安定化という原因仮説を示した。さらにGC/AGCが発散直前に十分小さなクリッピング係数を出せない点を学習ダイナミクスの観察から指摘し、感度の高い手法で解決した。

**技術や手法のキモはどこ？**

ClippyはAdagradの勾配ではなく実際の更新量 r_t = g_t·G_t^&#123;-1/2} を対象に、L2ノルムではなくL∞ノルム（要素ごとの最大値）で更新量とパラメータの比を測り、更新をスケールダウンする。クリッピング係数は min&#123;1, (λ_rel|w|+λ_abs)/(η_t|r_t|)} で、絶対閾値λ_absによりパラメータがゼロ付近では初期にGC的、後半はAGC的に振る舞う。学習率を分母に入れてウォームアップに対応し、クリッピングは層ごとに適用する。他のオプティマイザにも更新量 r_t を差し替えれば適用できる。

**どうやって有効だと検証した？**

YouTube本番データで、Small（7.5M）、Large（57.0M）、Large+DCN（68.0M）の3構成を用い、AUCとRMSEを評価した。何も対策しないNaive手法は全構成で発散し、GC・AGC・LAMBは学習率が制限されるか収束が劣った。Clippyは全構成で2倍の学習率で学習でき、Large+DCNではAUC 72.37に対しGCは72.27、RMSEは1.047に対し1.051と最良だった。付録のTransformer翻訳タスクでもAdagrad+Clippyは発散しなかった（ただしAdamWの検証誤差率31.6%に対し33.4%）。

**議論はある？**

Clippyの理論的な収束解析は今後の課題とされている。また学習安定性を事前に定量評価する信頼できる指標がなく、評価は複数回の学習による経験的なものにとどまる。さらに実験は簡略化したモデルが中心で、検証も3回の繰り返しと限られている。

**次に読むべき論文は？**

- A Loss Curvature Perspective on Training Instability in Deep Learning：学習不安定性の原因を損失曲率（シャープネス）の観点から説明しており、本論文の理論的背景を理解できる。
- High-performance large-scale image recognition without normalization：比較対象であるAdaptive Gradient Clipping (AGC) の原論文で、Clippyとの違いを正確に把握できる。
- Recommending what video to watch next: a multitask ranking system：本論文が対象とするYouTubeのマルチタスクランキングモデルの詳細が書かれている。

:::


### 3. 多様性とプライバシー保護を両立する反実仮想説明のための特徴量ベース学習 {#paper-3}

🏆 Best Student Paper（研究トラック） ・ Vy Vo, Trung Le, Van Nguyen, He Zhao ほか ・ [論文を読む ↗](https://arxiv.org/abs/2209.13446)

<small>原題: Feature-based Learning for Diverse and Privacy-Preserving Counterfactual Explanations</small>

ブラックボックス分類器への反実仮想説明（アルゴリズミック・リコース）を、多様性・スパース性・実行可能性・妥当性・スケーラビリティ・プライバシー保護を同時に満たして生成する枠組み L2C を提案した研究です。特徴量ごとの摂動分布と選択分布を学習し、1つのモデルから多数の反実仮想例を効率よくサンプリングでき、連続特徴量の離散化でリンケージ攻撃のリスク低減を図る点が、プライバシー保護を内蔵した償却型エンジンとして新しいと主張されています。4つのデータセットで DICE、MCCE、COPA と比較し、Validity と Coverage が100%で推論時間も短い結果が示され、KDD 2023 の Best Student Paper（研究トラック）に選ばれました。

::: info 📝 落合フォーマット

**どんなもの？**

ブラックボックス分類器に対する反実仮想説明（アルゴリズミック・リコース）を、多様性・スパース性・実行可能性・妥当性・スケーラビリティ・プライバシー保護を同時に満たしつつ生成する枠組み L2C（Learning to Counter）を提案した研究。特徴量ごとの摂動分布と選択分布を学習し、1つのモデルから多数の反実仮想例を効率的にサンプリングできる。

**先行研究と比べてどこがすごい？**

多様な反実仮想を生成できる償却（amortized）型の手法として、プライバシー保護機能を内蔵した初のエンジンだと主張している。距離ベースのL1/L2ではなく、特徴量ごとのBernoulli選択でスパース性を制御し、単調性制約を確率分布に直接組み込む。連続特徴量を離散化してカテゴリ空間で生成することで、リンケージ攻撃（再識別）のリスクを下げる点も特徴で、CF-Kのように追加で大量のクエリを要するアドオン方式とは異なる。

**技術や手法のキモはどこ？**

入力の連続特徴量を等幅バケットに離散化しone-hot化し、ジェネレータ𝒢が各可変特徴量のカテゴリカル分布Cat(p_i|z)を、セレクタ𝒮が各特徴量を変更する確率のBernoulli(π_i|z)を出力する。サンプルはs_iに応じて元の値か摂動値を採用して結合し、連続特徴は区間の中点にone-hotデコードしてブラックボックスfに入力する。目的関数は目標ラベルy'に対するクロスエントロピーとπのL1正則化（スパース性）で、Gumbel-Softmaxによる再パラメータ化で微分可能にして𝒢と𝒮をエンドツーエンドで学習する。単調性制約は、禁止される水準の確率に微小値ε=e^-10を乗じて対応する。

**どうやって有効だと検証した？**

German Credit、Adult Income、Graduate Admission、Student Performanceの4データセットで、DICE、MCCE、COPAと比較した（5分の時間制限、100件の反実仮想生成、5回のモデル初期化の平均）。L2Cは全データセットでValidityとCoverageが100%で、単調性制約の遵守（Unary）もほぼ満たし、推論時間も短かった（例：German Creditで1秒台、DICEは数千〜1万秒超）。またスパース性と多様性の調和平均でも概ね良好で、German Creditの調和平均46.39%はDICE-Geneticを除く手法を上回る。再識別リスク分析（k-Anonymity、l-Diversity、k-Map）ではL2Cが最も低いリスクを示したとされるが、該当の数値は提示された本文には含まれていない。

**議論はある？**

二値の単調性制約など特徴量間の制約は本文では後半（5.4節）に回されており、主な分析は単項制約に限られる。離散化の粒度や、連続特徴量を区間の中点に復元する設計が説明の精度やプライバシーに与える影響は検討の余地がある。また、プライバシー保護は経験的な再識別指標での評価にとどまり、差分プライバシーのような理論的保証は与えられていない。

**次に読むべき論文は？**

- Explaining machine learning classifiers through diverse counterfactual explanations (DiCE)：多様な反実仮想生成の代表的ベースラインで、DPPによる多様性の定式化とL2Cとの違いを理解するために必要。
- The privacy issue of counterfactual explanations: explanation linkage attacks：反実仮想説明に対するリンケージ攻撃とCF-Kによる防御を扱っており、L2Cのプライバシー面の動機と比較対象を把握できる。
- Amortized Generation of Sequential Algorithmic Recourses for Black-Box Models (FastAR)：償却型の反実仮想生成で単調性などの制約を扱う先行手法であり、L2Cの効率性・妥当性の主張を比較して読める。

:::


### 4. Auto-WEKA: 分類アルゴリズムの選択とハイパーパラメータ最適化の統合的実施 {#paper-4}

🏆 Test of Time（研究） ・ Chris Thornton, Frank Hutter, Holger H. Hoos, Kevin Leyton-Brown ・ [論文を読む ↗](https://arxiv.org/abs/1208.3719)

<small>原題: Auto-WEKA: Combined Selection and Hyperparameter Optimization of Classification Algorithms</small>

分類アルゴリズムの選択とそのハイパーパラメータ設定を同時に解く問題を CASH として定式化し、WEKA の 39 分類器などを含む 786 次元の条件付き空間にベイズ最適化を適用する自動化ツール Auto-WEKA を提案した研究です。21 データセットでの実験では、テスト誤差で Ex-Def と Random Grid に 15/21 件で勝ち、最大規模の 11 データセットでは全てで最良となり、非専門家でも高性能な分類器を得られる可能性を示しました。KDD 2023 の Test of Time（研究）を受賞した点も注目される理由です。

::: info 📝 落合フォーマット

**どんなもの？**

分類アルゴリズムの選択とそのハイパーパラメータ設定を同時に自動で行う問題を CASH（Combined Algorithm Selection and Hyperparameter optimization）として定式化し、WEKA の全分類器と特徴選択手法を対象に解く自動化ツール Auto-WEKA を提案した研究。非専門家でも高性能な分類器を得られることを目指している。

**先行研究と比べてどこがすごい？**

モデル選択とハイパーパラメータ最適化は個別に研究されてきたが、両者を一つの階層的ハイパーパラメータ最適化問題（アルゴリズム選択自体をハイパーパラメータとみなす）として統合した点が新しい。著者らの調べでは CASH を扱った先行研究は見当たらないとされる。ベイズ最適化を、WEKA の 39 分類器と 3 つの探索法・8 つの評価器を含む 786 次元の条件付き空間に適用した。

**技術や手法のキモはどこ？**

アルゴリズムを選ぶルートレベルのパラメータを追加し、各アルゴリズムのパラメータをその条件付きパラメータとして木構造の空間にまとめる。これを階層構造を扱える逐次モデルベース最適化 SMBO の SMAC（ランダムフォレストによるモデルと期待改善量を使用）と TPE（良い設定と悪い設定の 2 つの密度推定を使用）で探索する。SMAC は交差検証の分割を 1 つずつ評価して悪い設定を早期に棄却する。計算資源は 4 並列の独立実行で、最良の交差検証誤差の結果を採用する。

**どうやって有効だと検証した？**

UCI、KDD Cup 09、MNIST 変種、CIFAR-10 を含む 21 データセットで、ベースライン（全 39 分類器の既定設定を比較する Ex-Def と、ランダムグリッド探索の Random Grid）と比較した。交差検証誤差では Auto-WEKA が Random Grid を 20/21 件で上回り、SMAC は TPE に 19/21 件で勝った。テスト誤差では Ex-Def と Random Grid に対して 15/21 件で勝ち（3 件は引き分け、3 件は負け）、最大規模の 11 データセットでは全てで最良だった。

**議論はある？**

探索空間が大きいため過適合のリスクがあり、交差検証誤差に比べてテスト誤差での改善は小さかった。過適合の検出に使う相関係数も弱い指標に過ぎないと著者ら自身が述べている。今後の課題として、より洗練された過適合対策、アンサンブル内でのパラメータ共有、最適化を内側ループとしたアンサンブル構築が挙げられている。

**次に読むべき論文は？**

- Sequential model-based optimization for general algorithm configuration：Auto-WEKA の中核最適化手法である SMAC の原論文で、条件付きパラメータの扱いを理解できる。
- Algorithms for Hyper-Parameter Optimization：もう一方の最適化手法 TPE を提案した論文で、木構造の探索空間でのハイパーパラメータ最適化を学べる。
- Random search for hyper-parameter optimization：ベースライン Random Grid の考え方であるランダム探索の有効性を示した論文である。

:::


### 5. CodeGeeX: コード生成のための事前学習モデルと、HumanEval-Xによる多言語ベンチマーク評価 {#paper-5}

📈 被引用数上位（Paper Digest の集計で同年1位） ・ Qinkai Zheng, Xiao Xia, Xu Zou, Yuxiao Dong ほか ・ [論文を読む ↗](https://arxiv.org/abs/2303.17568)

<small>原題: CodeGeeX: A Pre-Trained Model for Code Generation with Multilingual Benchmarking on HumanEval-X</small>

23種類のプログラミング言語・8500億トークンで事前学習した130億パラメータのコード生成モデルCodeGeeXを提案し、C++・Java・JavaScript・Goの解答を手書きしてHumanEvalを多言語化したHumanEval-Xも構築した研究です。Codexなど多くのモデルが非公開・Python中心であるなかで、モデル・重み・API・IDE拡張・ベンチマークをすべて公開した点が評価され、KDD 2023で被引用数が同年1位（Paper Digest集計）となりました。HumanEval-Xの5言語での評価では生成の平均pass@1/10/100が18.40%/33.29%/54.76%でCodeGen-Multi-16Bをわずかに上回り、全モデルで最高となり、168人のユーザー調査では83.4%が効率向上を実感したと報告されています。

::: info 📝 落合フォーマット

**どんなもの？**

23種類のプログラミング言語・8500億トークンで事前学習した130億パラメータの多言語コード生成モデルCodeGeeXを提案した研究。あわせて、C++・Java・JavaScript・Goの解答を手書きしてHumanEvalを多言語化したベンチマークHumanEval-Xを構築した。モデル・重み・API・IDE拡張・ベンチマークはすべて公開されている。

**先行研究と比べてどこがすごい？**

Codexなど多くの大規模コードモデルが非公開・Python中心であるのに対し、モデル本体と大規模事前学習の方法を公開した点が新しい。既存の多言語ベンチマークがBLEUなどの文字列類似度で評価していたのに対し、HumanEval-Xはテストケースによる機能的正しさ（pass@k）で、コード生成とコード翻訳の両方を評価できる。さらに多言語モデル向けに、複数言語へ生成予算を配分する評価指標を導入した。

**技術や手法のキモはどこ？**

GPT型のdecoder-onlyで、39層のTransformerデコーダの上にtop query layerを置き、FastGELUを用いて自己回帰的に次トークンを予測する。学習データは言語タグ付きの158Bトークン（The Pile、CodeParrot、GitHubから収集した補足データ）で、GPT-2のBPEトークナイザに連続空白用の追加トークンを加えている。1,536基のAscend 910（MindSpore）で、8並列のモデル並列、192並列のデータ並列、ZeRO-2を組み合わせて学習し、カーネル融合とAuto Tuneで学習効率を高めた。推論ではINT8量子化とFasterTransformerにより、メモリを約26.9GBから約14.7GBに削減した。

**どうやって有効だと検証した？**

HumanEval-Xの5言語でコード生成と翻訳（20言語ペア）を評価し、GPT-J-6B、GPT-NeoX-20B、InCoder-6.7B、CodeGen-Multi-6B/16Bと比較した。生成では平均pass@1/10/100が18.40%/33.29%/54.76%で、CodeGen-Multi-16B（16.73%/32.09%/54.39%）をわずかに上回り、全モデルで最高だった。翻訳では、微調整版CodeGeeX-13B-FTが20ペア中11ペアのpass@100で最良（CodeGen-Multi-16Bは7ペア）だった。複数言語への予算配分（Uniform/Weighted）は単一言語の最良よりpass@100が高く、168人のユーザー調査では83.4%が効率向上を実感した。

**議論はある？**

言語間の翻訳性能はA→BとB→Aで負の相関を示し、言語間の高次の理解がまだ不足している。Goなど学習データの少ない言語や、構文制約の厳しい言語は性能が低い。ユーザー調査ではプロの開発者の満足度に改善余地があり、学習データがオープンソースの入門・研究系コードに偏っていることが一因と考えられるため、実務コードや言語別データの拡充が今後の課題である。

**次に読むべき論文は？**

- Evaluating Large Language Models Trained on Code：HumanEvalとpass@kの定義、およびCodexの元論文であり、HumanEval-Xの土台を理解するために必要。
- A Conversational Paradigm for Program Synthesis：主要な比較対象であるCodeGenの設計と評価（MTPB）を理解できる。
- XLCoST: A Benchmark Dataset for Cross-Lingual Code Intelligence：CodeGeeX-13B-FTの翻訳タスクの微調整に用いられたデータセットを確認できる。

:::

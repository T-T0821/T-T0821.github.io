# KDD 2026

🔎 データマイニング・Web ・ [KDD の年ごとの流れ](./) ・ [公式サイト ↗](https://kdd.org/)

::: info この回のまとめ
KDD 2026 は2026年8月9〜13日に韓国の済州島で開催されました。研究トラックの最優秀論文は、ベクトル検索で使うグラフ型の近傍探索索引を、ランダムアクセスの多い探索に頼らず行列演算でまとめて作ることで超高速に構築する PiPNN です。ADS トラックでは、保護すべきグループを指定せずにサブグループごとの予測の較正（マルチキャリブレーション）を大規模に行う MCGrad、データセット・ベンチマークトラックでは画像と複数ターンを含む RAG のベンチマーク CRAG-MM が選ばれました。Test of Time 賞は XGBoost でした。
:::

- **日程**: 2026年8月9日〜13日
- **開催地**: 韓国・済州島

**📝 注目論文（2 本）**

1. [PiPNN: 超大規模に対応するグラフ型の近傍探索索引](#paper-1)

## 🔭 この回の主なテーマ

- ベクトル検索の基盤: 近傍探索索引の構築を行列演算で高速化（PiPNN）
- 予測の信頼性: グループを指定しないマルチキャリブレーションの実運用（MCGrad）
- RAG の評価: 画像を含む複数ターンの RAG ベンチマーク（CRAG-MM）
- 複合 AI システム: 品質制約のもとで費用を抑えるモデル選択（最優秀学生論文）
- 推薦の生成モデル化: 生成的な再ランキング、EC の因果的な配信最適化（ADS 次点・佳作）

::: tip 💡 技術動向への示唆
- RAG やエージェントを支えるベクトル検索の索引構築が最高賞を得ており、LLM 時代のデータ基盤技術としてデータマイニング分野の役割が増している
- 複数のモデルを組み合わせる複合 AI システムの費用対効果を扱う研究が出てきており、LLM 活用のコスト最適化が研究テーマになっている
:::

## 📝 注目論文

### 1. PiPNN: 超大規模に対応するグラフ型の近傍探索索引 {#paper-1}

🏆 Best Paper（研究トラック） ・ Tobias Rubel, Richard Wen, Laxman Dhulipala, Lars Gottesbüren ほか ・ [論文を読む ↗](https://arxiv.org/abs/2602.21247)

<small>原題: PiPNN: Ultra-Scalable Graph-based Nearest Neighbor Indexing</small>

HNSW などのグラフ型索引は検索が速い一方、構築にランダムアクセスの多い探索が必要で時間がかかります。データを重なりのある部分問題に分け、行列演算でまとめて距離を計算し、新しい枝刈り HashPrune で辺を管理することで、構築を大幅に高速化しました。

::: info 📝 落合フォーマット

**どんなもの？**

グラフ型の近似最近傍探索(ANNS)インデックスの構築が極めて遅いという問題に対し、ビームサーチを構築時に使わない超スケーラブルなグラフ構築アルゴリズムPiPNN(Pick-in-Partitions Nearest Neighbors)を提案した研究。HNSWやVamanaと同等の検索品質を保ちつつ、構築時間を大幅に短縮し、10億点規模のデータでも単一マルチコアマシンで20分未満の構築を可能にした。

**先行研究と比べてどこがすごい？**

従来のHNSW/Vamanaは挿入ごとのビームサーチ(ランダムメモリアクセス中心)がボトルネックだったが、PiPNNは検索を構築過程から完全に排除した。また、パーティション分割方式(HCNNGなど)が抱えていた「候補が膨大でオフライン枝刈りができない」問題を、履歴非依存(history-independent)でメモリ上限が保証されるオンライン枝刈りHashPruneによって解決した点が新しい。

**技術や手法のキモはどこ？**

(1) Randomized Ball Carvingでデータを小さな重複パーティション(リーフ、最大1024〜2048点程度)に分割し、複数リーダーへのfanout(多段fanout含む)で重複を作る。(2) 各リーフ内でGEMM(Eigen)により全点対距離を一括計算し、リーフ内k-NNグラフを双方向化して候補エッジを選ぶ。(3) HashPruneがLSH(残差に対するm本の超平面による符号ハッシュ)で方向的に似た候補を同一バケットとみなし、各バケットで最も近い候補のみを固定サイズのリザーバ(1スロット8バイト)に保持する。必要に応じて最後にRobustPruneをかける。

**どうやって有効だと検証した？**

BigANN・DEEP・MS-SPACEV・MS-Turing(各10億点)と、Wikipedia-Cohere・OpenAI-ArXivの計6データセットで、QPS対再現率(10@10 recall)と構築時間をHNSW、Vamana、HCNNG、MIRAGE、FastKCNAと比較した。同等品質のインデックスをVamanaより最大11.6倍(平均6.32倍)、HNSWより最大12.9倍(平均10.4倍)高速に構築し、MIRAGEより19.1倍以上、FastKCNAより17.3倍以上高速だった。また、キャッシュミスとサイクル数がVamana/HNSWより桁違いに少なく、IPCも1.26(対0.44、0.33)と良好で、近似k-NNグラフ構築でも最大1.9倍の高速化を示した。

**議論はある？**

MIRAGEとFastKCNAはメモリ不足で10億点規模では動作せず、MIRAGEは100M規模でも再現率0.8を超えられなかったため、比較はこれらの手法については小〜中規模に限られる。HashPruneのリザーバ管理は最適化の余地があるが、構築時間の5%以下で、全体への影響は小さいと述べられている。なお、本文は途中が省略されており、付録の詳細(メモリ使用量の全比較など)は確認できていない。

**次に読むべき論文は？**

- DiskANN: Fast Accurate Billion-point Nearest Neighbor Search on a Single Node：PiPNNの主要比較対象であるVamanaとRobustPruneの原典で、PiPNNが回避しようとした挿入型構築の仕組みを理解できる。
- ParlayANN: Scalable and Deterministic Parallel Graph-Based Approximate Nearest Neighbor Search Algorithms：PiPNNが比較に用いた最速のVamana/HCNNG実装と、ベンチマーク設定の基盤を把握できる。
- Hierarchical clustering-based graphs for large scale approximate nearest neighbor search：パーティション型のグラフ構築であるHCNNGの原典で、PiPNNが解決した「和集合による密なグラフ化」の課題を理解できる。

:::


### 2. MCGrad: Web 規模のマルチキャリブレーション {#paper-2}

🏆 Best Paper（ADS トラック） ・ Niek Tax, Lorenzo Perini, Fridolin Linder, Daniel Haimovich ・ [論文を読む ↗](https://arxiv.org/abs/2509.19884)

<small>原題: MCGrad: Multicalibration at Web Scale</small>

サブグループごとに予測確率を正しくそろえるマルチキャリブレーションは、グループの事前指定が必要、規模に耐えない、他の指標を悪化させうる、という理由で実務に広まっていませんでした。これらを解決し、実運用で使える形にしました。

::: info 📝 落合フォーマット

**どんなもの？**

MCGrad（MultiCalibration Gradient boosting）は、保護グループを明示的に指定せずに、保護したい特徴量の集合だけから多重校正（multicalibration）を達成するポストプロセッシング手法である。スケーラブルでありながら、log lossやPRAUCといった他の性能指標を悪化させないことを目指している。Metaで数百の本番モデルに導入され、公開データセットでも評価されている。

**先行研究と比べてどこがすごい？**

既存手法が抱える3つの課題（保護グループの手動指定が必要、スケールしない、log lossやPRAUCを損なう恐れがある）をまとめて解消した点が新しい。グループの二値メンバーシップ指標を与える代わりに特徴量だけを与えればよく、グループ数が増えても推論時間がほぼ一定である。著者らは、本論文が多重校正の本番導入として最大規模だと主張している。

**技術や手法のキモはどこ？**

ベース予測値を特徴量として加えたGBDT（LightGBM）を再帰的に複数ラウンド適用し、各ラウンドで前ラウンドの予測を入力に使うことで、多重校正された予測器に収束させる。各ラウンド後にロジット全体を定数θで再スケーリングし、シュリンケージによる過小スケールを補正して必要なツリー数とラウンド数を減らす。過学習対策として、検証損失に基づくラウンド数の早期停止（初回で悪化する場合はT=0でベース予測をそのまま使う）と、葉のHessian和の下限（min sum Hessian in leaf）による正則化を導入している。

**どうやって有効だと検証した？**

11の公開ベンチマーク（ACS系、MEPS、Credit、Marketing、HMDAなど）で、DFMC、HKRR、Isotonicと比較し、多重校正誤差（MCE）を主指標とした。未指定グループに対するMCEは11データセット中10で最良となり、ベース予測器に対する平均削減率は56.1%（DFMC 11.9%、Isotonic 9.6%、HKRR 1.4%）、平均log loss改善は10.4%、PRAUC改善は8.1%だった。1000グループ時の推論遅延は約20μsで、HKRRの5019μs、DFMCの1292μsと比べ、遅延オーバーヘッドは2%未満である。本番ではLooper上の27モデル中24でPlatt scalingを統計的有意に上回り、MLplatform#2の120以上のモデルでは、log lossが88.7%、PRAUCが76.7%、ECEが86.0%のモデルで改善した。

**議論はある？**

事前指定グループに対するMCEでは、11データセット中5つでのみ最良にとどまり、グループに直接アクセスできるDFMCが3データセットで上回った。また、MLplatform#2の一部モデルではPRAUCやECEが悪化しており（90パーセンタイルでPRAUC -2.07%〜-4.85%）、全モデルで改善するわけではない。再スケーリングやHessian正則化の効果は、小規模データでは軽微にとどまるため、大規模データでの検証が重要と考えられる。なお、提示された本文は途中で省略されており、理論的な収束保証（付録B）や実運用上の知見（第6節）は確認できていない。

**次に読むべき論文は？**

- Multicalibration: Calibration for the (Computationally-identifiable) Masses：多重校正の基礎となる古典的アルゴリズム（HKRR）であり、MCGradの比較対象と問題設定を理解するために必要。
- Measuring multi-calibration：本論文の評価に用いられた多重校正誤差（MCE）の定義と、ECCEに基づく測定法の詳細が書かれている。
- Discretization-free multicalibration through loss minimization over tree ensembles：同じくツリーアンサンブルで多重校正を行う直接の競合手法（DFMC）であり、MCGradとの違いを把握できる。

:::

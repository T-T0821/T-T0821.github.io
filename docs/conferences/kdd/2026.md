# KDD 2026

🔎 データマイニング・Web ・ [KDD の年ごとの流れ](./) ・ [公式サイト ↗](https://kdd.org/)

::: info この回のまとめ
KDD 2026 は2026年8月9〜13日に韓国の済州島で開催されました。研究トラックの最優秀論文は、ベクトル検索で使うグラフ型の近傍探索索引を、ランダムアクセスの多い探索に頼らず行列演算でまとめて作ることで超高速に構築する PiPNN です。ADS トラックでは、保護すべきグループを指定せずにサブグループごとの予測の較正（マルチキャリブレーション）を大規模に行う MCGrad、データセット・ベンチマークトラックでは画像と複数ターンを含む RAG のベンチマーク CRAG-MM が選ばれました。Test of Time 賞は XGBoost でした。
:::

### 1. PiPNN: 超大規模に対応するグラフ型の近傍探索索引 {#paper-1}

🏆 Best Paper（研究トラック） ・ Tobias Rubel, Richard Wen, Laxman Dhulipala, Lars Gottesbüren ほか ・ [論文を読む ↗](https://arxiv.org/abs/2602.21247)

<small>原題: PiPNN: Ultra-Scalable Graph-based Nearest Neighbor Indexing</small>

HNSW などのグラフ型索引は検索が速い一方、構築にランダムアクセスの多い探索が必要で時間がかかります。データを重なりのある部分問題に分け、行列演算でまとめて距離を計算し、新しい枝刈り HashPrune で辺を管理することで、構築を大幅に高速化しました。

::: info 📝 落合フォーマット

**どんなもの？**

グラフ型の近似最近傍探索(ANNS)インデックスの構築が極めて遅いという問題に対し、ビームサーチを構築時に使わない超スケーラブルなグラフ構築アルゴリズムPiPNN(Pick-in-Partitions Nearest Neighbors)を提案した研究。HNSWやVamanaと同等の検索品質を保ちつつ、構築時間を大幅に短縮し、10億点規模のデータでも単一マルチコアマシンで20分未満の構築を可能にした。

**先行研究と比べてどこがすごい？**

従来のHNSW/Vamanaは挿入ごとのビームサーチ(ランダムメモリアクセス中心)がボトルネックだったが、PiPNNは検索を構築過程から完全に排除した。また、パーティション分割方式(HCNNGなど)が抱えていた「候補が膨大でオフライン枝刈りができない」問題を、履歴非依存(history-independent)でメモリ上限が保証されるオンライン枝刈りHashPruneによって解決した点が新しい。

**技術や手法のキモはどこ？**

(1) Randomized Ball Carvingでデータを小さな重複パーティション(リーフ、最大1024〜2048点程度)に分割し、複数リーダーへのfanout(多段fanout含む)で重複を作る。(2) 各リーフ内でGEMM(Eigen)により全点対距離を一括計算し、リーフ内k-NNグラフを双方向化して候補エッジを選ぶ。(3) HashPruneがLSH(残差に対するm本の超平面による符号ハッシュ)で方向的に似た候補を同一バケットとみなし、各バケットで最も近い候補のみを固定サイズのリザーバ(1スロット8バイト)に保持する。必要に応じて最後にRobustPruneをかける。

**どうやって有効だと検証した？**

BigANN・DEEP・MS-SPACEV・MS-Turing(各10億点)と、Wikipedia-Cohere・OpenAI-ArXivの計6データセットで、QPS対再現率(10@10 recall)と構築時間をHNSW、Vamana、HCNNG、MIRAGE、FastKCNAと比較した。同等品質のインデックスをVamanaより最大11.6倍(平均6.32倍)、HNSWより最大12.9倍(平均10.4倍)高速に構築し、MIRAGEより19.1倍以上、FastKCNAより17.3倍以上高速だった。また、キャッシュミスとサイクル数がVamana/HNSWより桁違いに少なく、IPCも1.26(対0.44、0.33)と良好で、近似k-NNグラフ構築でも最大1.9倍の高速化を示した。

**議論はある？**

MIRAGEとFastKCNAはメモリ不足で10億点規模では動作せず、MIRAGEは100M規模でも再現率0.8を超えられなかったため、比較はこれらの手法については小〜中規模に限られる。HashPruneのリザーバ管理は最適化の余地があるが、構築時間の5%以下で、全体への影響は小さいと述べられている。なお、本文は途中が省略されており、付録の詳細(メモリ使用量の全比較など)は確認できていない。

**次に読むべき論文は？**

- DiskANN: Fast Accurate Billion-point Nearest Neighbor Search on a Single Node：PiPNNの主要比較対象であるVamanaとRobustPruneの原典で、PiPNNが回避しようとした挿入型構築の仕組みを理解できる。
- ParlayANN: Scalable and Deterministic Parallel Graph-Based Approximate Nearest Neighbor Search Algorithms：PiPNNが比較に用いた最速のVamana/HCNNG実装と、ベンチマーク設定の基盤を把握できる。
- Hierarchical clustering-based graphs for large scale approximate nearest neighbor search：パーティション型のグラフ構築であるHCNNGの原典で、PiPNNが解決した「和集合による密なグラフ化」の課題を理解できる。

:::


### 2. MCGrad: Web 規模のマルチキャリブレーション {#paper-2}

🏆 Best Paper（ADS トラック） ・ Niek Tax, Lorenzo Perini, Fridolin Linder, Daniel Haimovich ・ [論文を読む ↗](https://arxiv.org/abs/2509.19884)

<small>原題: MCGrad: Multicalibration at Web Scale</small>

サブグループごとに予測確率を正しくそろえるマルチキャリブレーションは、グループの事前指定が必要、規模に耐えない、他の指標を悪化させうる、という理由で実務に広まっていませんでした。これらを解決し、実運用で使える形にしました。

::: info 📝 落合フォーマット

**どんなもの？**

MCGrad（MultiCalibration Gradient boosting）は、保護グループを明示的に指定せずに、保護したい特徴量の集合だけから多重校正（multicalibration）を達成するポストプロセッシング手法である。スケーラブルでありながら、log lossやPRAUCといった他の性能指標を悪化させないことを目指している。Metaで数百の本番モデルに導入され、公開データセットでも評価されている。

**先行研究と比べてどこがすごい？**

既存手法が抱える3つの課題（保護グループの手動指定が必要、スケールしない、log lossやPRAUCを損なう恐れがある）をまとめて解消した点が新しい。グループの二値メンバーシップ指標を与える代わりに特徴量だけを与えればよく、グループ数が増えても推論時間がほぼ一定である。著者らは、本論文が多重校正の本番導入として最大規模だと主張している。

**技術や手法のキモはどこ？**

ベース予測値を特徴量として加えたGBDT（LightGBM）を再帰的に複数ラウンド適用し、各ラウンドで前ラウンドの予測を入力に使うことで、多重校正された予測器に収束させる。各ラウンド後にロジット全体を定数θで再スケーリングし、シュリンケージによる過小スケールを補正して必要なツリー数とラウンド数を減らす。過学習対策として、検証損失に基づくラウンド数の早期停止（初回で悪化する場合はT=0でベース予測をそのまま使う）と、葉のHessian和の下限（min sum Hessian in leaf）による正則化を導入している。

**どうやって有効だと検証した？**

11の公開ベンチマーク（ACS系、MEPS、Credit、Marketing、HMDAなど）で、DFMC、HKRR、Isotonicと比較し、多重校正誤差（MCE）を主指標とした。未指定グループに対するMCEは11データセット中10で最良となり、ベース予測器に対する平均削減率は56.1%（DFMC 11.9%、Isotonic 9.6%、HKRR 1.4%）、平均log loss改善は10.4%、PRAUC改善は8.1%だった。1000グループ時の推論遅延は約20μsで、HKRRの5019μs、DFMCの1292μsと比べ、遅延オーバーヘッドは2%未満である。本番ではLooper上の27モデル中24でPlatt scalingを統計的有意に上回り、MLplatform#2の120以上のモデルでは、log lossが88.7%、PRAUCが76.7%、ECEが86.0%のモデルで改善した。

**議論はある？**

事前指定グループに対するMCEでは、11データセット中5つでのみ最良にとどまり、グループに直接アクセスできるDFMCが3データセットで上回った。また、MLplatform#2の一部モデルではPRAUCやECEが悪化しており（90パーセンタイルでPRAUC -2.07%〜-4.85%）、全モデルで改善するわけではない。再スケーリングやHessian正則化の効果は、小規模データでは軽微にとどまるため、大規模データでの検証が重要と考えられる。なお、提示された本文は途中で省略されており、理論的な収束保証（付録B）や実運用上の知見（第6節）は確認できていない。

**次に読むべき論文は？**

- Multicalibration: Calibration for the (Computationally-identifiable) Masses：多重校正の基礎となる古典的アルゴリズム（HKRR）であり、MCGradの比較対象と問題設定を理解するために必要。
- Measuring multi-calibration：本論文の評価に用いられた多重校正誤差（MCE）の定義と、ECCEに基づく測定法の詳細が書かれている。
- Discretization-free multicalibration through loss minimization over tree ensembles：同じくツリーアンサンブルで多重校正を行う直接の競合手法（DFMC）であり、MCGradとの違いを把握できる。

:::


### 3. CRAG-MM: マルチモーダル・マルチターンの包括的RAGベンチマーク {#paper-3}

🏆 Best Paper（データセット・ベンチマーク） ・ Jiaqi Wang, Xiao Yang, Kai Sun, Parth Suresh ほか ・ [論文を読む ↗](https://arxiv.org/abs/2510.26160)

<small>原題: CRAG-MM: Multi-modal Multi-turn Comprehensive RAG Benchmark</small>

スマートグラスなどウェアラブル端末で「見ているものについて質問する」場面を想定し、13ドメインの単発6.5Kとマルチターン2Kの会話を含むMM-RAGベンチマークCRAG-MMを、画像KG検索・Web検索APIとともに公開した研究です。低照度やブレなどを含む一人称視点画像、トーソ〜テールのentity、ドメイン遷移を伴う会話を同時に扱う点が、既存ベンチマークと異なります。評価ではGPT-5 Miniを使った素朴なRAGでも単発32%・マルチターン43%、産業界のSOTAシステムも32%/45%程度にとどまり、課題の大きさが示されました。KDD Cup 2025の優勝解法は素朴なRAGに対し単発+28%、マルチターン+18%の改善を示しており、KDD 2026のデータセット・ベンチマーク部門でBest Paperを受賞しています。

::: info 📝 落合フォーマット

**どんなもの？**

スマートグラスなどウェアラブル端末での「見ているものについて質問する」利用場面を想定した、マルチモーダルRAG（MM-RAG）の包括的ベンチマークCRAG-MMを提案した研究。13ドメインにわたる6.5Kの単発(画像・質問・回答)と2Kのマルチターン会話（画像は計7.9K、うち6.2Kが一人称視点画像）を提供する。画像KG検索とWeb検索のAPIも併せて公開し、公平な比較を可能にしている。

**先行研究と比べてどこがすごい？**

既存のVQAや知識ベースVQAは高品質画像、Wikipedia由来、テンプレート生成、非現実的な質問が中心だったが、本ベンチマークはウェアラブル由来の低品質な一人称視点画像（低照度・ブレ・切れ・遮蔽・回転）、トーソ〜テール entity、ドメイン遷移を含むマルチターン会話を同時に扱う。画像検索API・Web検索API・マルチモーダル・マルチターン・一人称画像・トーソ&テール事実をすべて備える点で、比較表中の既存ベンチマークと差別化している（論文は「初の公開MM-RAGベンチマーク」と主張）。

**技術や手法のキモはどこ？**

画像品質(5種)・質問タイプ(6種：simple-recognition/simple-knowledge/multi-hop/comparison/aggregation/reasoning)・entity人気度・会話の複雑さの4軸で設計。KG由来の質問はテンプレートで、Web由来の質問はアノテータが作成し、マルチターンはLlama-3.2-90B-Visionで生成後に人手で修正した。Task1（画像KG検索）、Task2（画像KG+Web検索）、Task3（マルチターン）を設定し、CLIP ViT-L/14@336pxによる画像検索（ハードネガティブ付き68K画像KG）とBGEによるWeb検索（800Kページ）のモックAPIを用意。評価は正解+1／無回答0／誤答−1の平均Truthfulnessで、マルチターンは2連続の誤答・無回答で会話を打ち切り、GPT-4oをLLM-as-a-judgeに用いる。

**どうやって有効だと検証した？**

公開テストセットで、MM-LLM単体の最良（GPT-5 Mini）は単発のTruthfulness 18%、マルチターン30%。素朴なRAGでも単発32%（Task2、GPT-5 Mini）、マルチターン43%（Task3）にとどまった。産業界のSOTAシステム（GPT-5等）も32%/45%程度で、ハルシネーション率は単発31〜49%と高い。KDD Cup 2025（約1K参加者・5K投稿）の優勝解法は同一ベースモデルの素朴なRAGに対し単発+28%、マルチターン+18%の改善を示した。低品質画像、テキスト手がかりのない認識、低人気entity、比較・集約・multi-hop、会話履歴依存の質問で性能が低下することが分析で示された。

**議論はある？**

産業SOTA・優勝解法・素朴な解法は使用モデル、検索コーパス、評価用テストセット（優勝解法は非公開テスト、他は公開テスト）が異なり、スコアを厳密には比較できないと著者自身が述べている。低品質画像、entity認識、複数情報の統合、マルチターン文脈理解、ハルシネーション抑制と適切な棄権のバランスなどが今後の改善課題として示されている。なお、データは英語のみである。

**次に読むべき論文は？**

- CRAG -- Comprehensive RAG Benchmark：CRAG-MMの設計思想・評価指標（Truthfulness等）の元になったテキストRAGベンチマークで、前提理解に必須である。
- SnapNTell: Enhancing Entity-Centric Visual Question Answering with Retrieval Augmented Multimodal LLM：エンティティ中心のマルチモーダルRAGを扱う近い先行研究で、CRAG-MMとの違いを把握できる。
- LLMs Get Lost in Multi-Turn Conversation：CRAG-MMでマルチターンの性能低下が確認された点と整合する知見を扱っており、会話履歴依存の課題の背景を理解できる。

:::


### 4. Pinterest における効率的なEコマース配信のための深層学習ベース因果リトリーバル最適化 {#paper-4}

🏆 Runner-up（ADS トラック） ・ Junpeng Hou, XianXing Zhang, Sai Xiao, Derek Cheng ほか ・ [論文を読む ↗](https://arxiv.org/abs/2607.14161)

<small>原題: Deep-learning Causal Retrieval Optimization for Efficient E-Commerce Distribution in Pinterest</small>

Pinterest の Closeup 画面で、ショッピング候補生成器をいつ起動するかを因果的な意思決定問題として定式化し、二重頑健（DR）擬似アウトカムによるアップリフト学習とマルチタスク深層モデルで個人・文脈ごとの起動ポリシーを学習した本番システムの研究です。オンラインではショッピング起動を最大85%削減しても全サイトSLFは中立で、約40%削減のグループでは Repins（Closeup）+1.10% や約50万の追加コスト削減を達成し、レイテンシ悪化もありませんでした。ランダム化ホールドアウトと線形時間のオフラインリプレイでしきい値選択とトリガー率をオンライン結果とよく一致させられる点も、実運用の観点から注目されます。

::: info 📝 落合フォーマット

**どんなもの？**

Pinterest の Closeup 画面で、早期リトリーバル段階においてショッピング候補生成器（CG）を「いつ起動するか」を因果的な意思決定問題として定式化し、個人・文脈ごとの起動ポリシーを学習する本番システムを構築した研究。深層マルチタスクモデルで複数イベントの結果とアップリフトを同時に予測し、不要な起動を減らしつつ主要なショッピング指標を維持する。

**先行研究と比べてどこがすごい？**

二重頑健（DR）擬似アウトカムによるアップリフト学習を、較正済みアウトカム損失やマルチタスク構造と組み合わせて深層モデルに適用し、早期リトリーバルのトリガー最適化に持ち込んだ点が新しい。また、ランダム化ホールドアウトと線形時間のオフラインリプレイにより、しきい値選択と効果予測をオンライン結果と高い一貫性で行えるようにした。通常指標に加えてリバース指標（R-PR AUC, R-P@K など）で評価する点も特徴である。

**技術や手法のキモはどこ？**

リクエスト（ユーザー・文脈・クエリ）を入力とし、DCNv2 で特徴交差、MMoE でマルチタスク化したモデルが、y=0/1 それぞれのアウトカム、傾向スコア、アップリフトの各ヘッドを出力する。損失はアウトカム損失、傾向損失、アップリフトとアウトカム差の整合を取る正則化損失、Switch-DR 型の切り捨てを入れた DR 擬似アウトカムの MSE 損失の和で、スパースなイベントには重みを上げる。データは Shopping Holdout 内で 50/50 にランダム化して収集する。オフラインリプレイは予測値でソートし、しきい値を動かしながらログ上の割当てとポリシー判断が一致する要求だけを集計して、トリガー率と指標をしきい値ごとに求める。本番ではスコア閾値で判定する単一値（SV）ポリシーを主に使い、アップリフトに基づく delta policy（DP）は診断用とする。

**どうやって有効だと検証した？**

Closeup のデータで 14 日分を学習、1 日分を評価に用い、AUC は飽和しているため P@K・R@K とそのリバース版で評価した。SLF ヘッドでは DR＋大型モデルが標準指標で最も高く、リバース指標でも低減を示した。オフラインリプレイとオンラインのトリガー率は、しきい値ごとに数ポイント以内でよく一致した。オンラインではショッピング起動を最大 85% 削減しつつ全サイト SLF は有意差なし（中立）だった。約 40% 削減のグループでは Repins（Closeup）+1.10%、Success Curation +0.26% などの向上と、約 50 万の追加コスト削減が得られ、レイテンシ悪化はなかった。

**議論はある？**

リプレイはオーバーラップ、ランダム化、リプレイ単位間の干渉なしという仮定に依存し、分布シフトが大きいと妥当性が下がる。DP はアップリフトの分散が大きく、リプレイとオンラインの一貫性が低いため、アンサンブルや不確実性を考慮したフィルタリングなどの改善が今後の課題とされている。モデルの大型化だけでは AUC が改善せず、フィードバックループや複数 CG・連続値トリガーへの拡張、ランダム化トラフィックが少ない小規模サービスへの適用も今後の検討事項として挙げられている。

**次に読むべき論文は？**

- Top-K Off-Policy Correction for a REINFORCE Recommender System：大規模推薦でログデータからオフポリシー学習を行う代表的手法で、本研究のカウンターファクチュアルなポリシー学習の背景を理解できる。
- Off-policy Learning in Two-stage Recommender Systems：第1段（候補生成）を後段のランカーとの相互作用を考慮して学習する枠組みで、早期リトリーバルのトリガー最適化と直接関係する。
- Doubly Robust Off-policy Value Evaluation for Ranking Policies under the Cascade Model：本研究が損失設計とオフライン評価の基盤とする二重頑健推定を、カスケード型ランキングに適用した手法を確認できる。
